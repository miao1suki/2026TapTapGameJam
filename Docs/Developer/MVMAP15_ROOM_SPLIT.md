# Gaming：MVMap15 房间划分

> 历史阶段。当前关卡已按MVMap16重新分房并配置类型，见[MVMAP16_LAYOUT.md](MVMAP16_LAYOUT.md)。

按用户确认，使用最新MVMap15紫色方块划分当前关卡：Unity中横向紫条取上边缘、纵向紫条取右边缘。继续沿用ef1b103的地图朝向，JSON单格(x,y)对应Unity单格(x,-y-1)。厚条只取外侧边，交会处连续连接。

紫色只提供区域边界，不生成实体、不删除其占格宽度、不平移现有地形。不自动延长断口，因此未被紫线封闭的区域保持连通。当前得到18个互不重叠的区域（包括外侧区域及无方块的围合区域），不是按全图横竖坐标无限延伸切片。

## 保留当前制作内容

- 采用任务开始时本地Gaming.planning.json的857项实际编辑内容，包括作者新增水源、墙、平台、植物、收集品、钥匙及已删除的一处白块；不按新JSON重建方块。
- 18个跨分界白色合并体拆为各房间内的精确形状，孔洞保留；其余物体ID、占格与参数保留，玩家出生点、相机位置和Camera/Side2D size8不变。
- 本地存在一条8格旧白色合并体与8个新单格白块完全重叠。保留8个新单格，去掉旧合并体的重复表示；实际地形没有增减。清单sharedCells逐格记录原物体到保留物体的对应。最终876项（857项+20份跨房间片段-1重复体）。
- 每个物体的RoomResetObject归属与房间实际占格一致；只维护作者数据，未修改运行时重生/颜色/机关规则。

源图、逐物体对应与房间计数见`Ops/LevelMaps/Map15/source.mvmap.json`和`room-layout-manifest.json`；紫线及房间预览见同目录`rooms-preview.png`。预览中的白色为白块、蓝色为作者道具，背景色表示区域，不是游戏美术。
