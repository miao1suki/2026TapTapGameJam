# m_room_2 关卡

独立场景：`Assets/Scenes/MRoom2.unity`。可编辑存档：同目录 `MRoom2.planning.json`；原始设计文件保存在 `MRoom2.mvmap.json`。

打开场景后按 M 打开关卡编辑器；W 切世界图，R 切房间详情，也可使用装配图。当前场景会自动恢复对应规划存档，不需要重新导入 MVMap。修改后保存规划和场景，一起交付两个文件及各自的 `.meta`。

## 布置

按 JSON 的对象名称映射，不使用颜色猜测或截图中偏移的文字。墙、水、植物障碍、岩浆保留原始占格与孔洞；连续矩形作为可编辑合并对象，藤蔓逐格生成并交由现有链接逻辑连接母根/节段。收集品、弹性植物、接触方块、重生点、基座、曲柄均使用现有正式道具预制体。梯子使用侧面梯子。

本图侧面梯子按标注的1、4、5、6格长度适配，保留攀爬Trigger，外观沿长度平铺；没有延长到相邻物体中。新放置正面、侧面梯子默认均1×1，已有两格梯子保留尺寸。合并对象包含原单元格快照，可在合并模式解除合并后继续编辑，再重新合并。

当前源为第二版 `m-room-2.mvmap (2).json`，24组名称按物体分类映射，不以颜色猜测。原图没有真正的房间/通道边界，因此只建立一个测试房间，覆盖新图完整范围。保留原坐标（MVMap 向下为正 Y，Unity 向上为正 Y），玩家位于原图格 `(-110,-8)` 的重生点附近，Unity 中心 `(-109.5,7.5,0)`。保留六个重生点；使用唯一标准 Player。颜色和能力默认锁定，不额外放钥匙；需要测试机关时用现有颜色调试工具解锁场景颜色。

## 平台配置

坐标均为原图占格矩形的左上格。路线行程指整个平台的平移距离，不是平台长度。

| 平台 | 尺寸 | 行程 | 控制器 |
|---|---|---|---|
| 左侧 `(-112,-24)` | 1×6 | 向上5格 | 基座 `(-108,-23)` |
| 托红块 `(-108,-20)` | 1×1 | 向上1格 | 同上基座 `(-108,-23)` |
| 中间右端 `(-84,-14)` | 4×1 | 向左35格 | 基座 `(-95,-13)` |
| 新增 `(-99,-23)` | 1×6 | 向下5格 | 基座2 `(-106,-25)` |
| 上方 `(-94,-19)` | 9×1 | 向右7格 | 曲柄 `(-92,-13)` |
| 下方 `(-110,0)` | 4×1 | 向右3格 | 曲柄 `(-110,2)` |

四个基座驱动平台使用“充能到终点，断电回原位”，充能到达首程端点后保持，断电沿原路返回布置位置；两个曲柄平台仍按曲柄进度前进/回退。托红块的平台共享左侧竖平台的基座；向上1格托住被绿钩子拉到基座下方的红块。所有三处基座保持无重力，可搬运规则不变。

中间横向路线 `X=-119…-85, Y=-14` 连续；补齐 `(-98,-14)`、`(-94,-14)` 植物占格，以及新增竖路线中 `(-99,-15)`、`(-99,-14)` 的遮挡缺口。路线预览共54格，托红块平台另由1格参数显示路线。路线是编辑器区域预览与平台参数，不生成墙、水或额外碰撞。终点模式遇到实际障碍会等待，清除后继续；路线连续不表示可以穿过未清除的实体障碍。

左下平台原始占格 `X=-110…-107, Y=0` 补入4格水，与平台处于独立编辑层；没有将整条路线自动灌水，也没有覆盖墙或替换原有水。七个一次保持按钮按名称后缀分别绑定门1/2/3，数量3/1/3；绑定顺序沿用各组源文件中的格子顺序，分别使用红/绿/蓝提示。两排尖刺均朝上。侧梯依邻墙选择左右版本，保留完整高度。

参数模式可修改各平台的路线、反向路线、距离、时间和绑定。绑定使用规划稳定 ID，场景重开、增量应用和区域重置均沿用同一关系，不依赖临时 instanceID。

第二版为用户指定的整图重导入，替换第一版的对象布局与实例ID，保留原Scene/存档/source的`.meta`。所有绑定使用本版稳定对象ID，合并快照和Scene同时写入，不残留旧`box_bb266cc9`等已替换对象引用。更完整的四向、双侧距离与中心偏移配置见 [机关与跳跃](MECHANISMS_AND_JUMP.md#移动路线与中心)。

这是独立测试关卡，不替代正式 Gaming，不加入正式打包场景列表。隔离作者/验证入口为 `MRoom2MapImport.Build`，只允许在 Library/FlowRetirementProbe 执行；不要在正在编辑的主项目中重复重建本图。

第二版覆盖前的三件原文件及meta备份位于`Library/MRoom2SecondImportBackup-20261017`，可在清理Library前恢复。主Unity若仍打开旧图，请重新加载MRoom2场景并关闭重开关卡编辑器，不要将旧内存规划保存回新版共享JSON。`MRoom2SecondImportAudit.Run`仅在隔离工程运行，验证实际供能与回位、托红块自保持、玩家承载、门按钮和房间复位；不等于完整关卡已通关。

## 2026-10-17 自动同步误删修复与恢复

打开窗口后墙/水大面积消失不是贴图或遮挡问题：旧版窗口会把前一次导入的会话绑定拿来与新地图比较，将重新分块、改坐标的对象当作手动删除。隔离实测同样从188项误删至104项，并清掉部分平台机关引用。

现已对删除记忆增加持久化文档版本校验，版本不符重新采集基线；打开期间生成实例被整体替换也先重新识别稳定ID/格，避免误删。仍支持同版手动删除和规划撤回，不关闭自动同步。

损坏时的Scene/规划/源图及其meta、此前完整验证副本均保存在 `Library/MRoom2AutosyncBackup-20261017`。本次从完整第二版恢复Scene和同名规划（188项、456墙格、61水格，其中4格在左下平台下），不回退到第一次导入，不新增截图中未提供JSON的内容，源图及meta不变。正式Gaming不受影响。再次打开前重新加载磁盘上的MRoom2，再重开关卡编辑器，避免继续使用旧内存状态。
