# MVMap 存档转换评估

普通 MVMap v1 导入保持布局模式，不转换 detail 灰盒；含外部门/锁/钥匙的文件暂拒绝。2026-10-14 新测试源图增加独立的临时颜色/形状物体转换，替换旧 MVMapImportTest Scene 和共享规划存档，见 [物体试导入](MVMAP_OBJECT_IMPORT.md)。下文是旧“主稿”的格式评估，不是当前测试图的映射结果。

## 样本

`map.mvmap.json`：格式版本 1，名称“主稿”，65 个房间、17,281 个占格、1 个区域；门、锁、钥匙均为空。只有两个房间存在 detail 条目，sub=8，boxes 均为空。坐标 X 为 -57 至 300，Y 为 -208 至 18。房间之间没有重复占格；17 个房间内部有不连通的部分。

## 可转换内容

- 房间 ID、名称、轮廓、负坐标可转成 PlanningRoom，字符串 `x,y` 转成 PlanningCell。可保留外部 ID，避免重复导入时丢失对应关系。
- 区域归属、颜色、备注可保留为规划信息；当前 PlanningRegion 是矩形，不能无损表示任意形状的区域分组，需要单独保存分组归属或拆成多个预览区域。现有房间着色主要由列表顺序推导，不能声称导入后已经精确保留外部颜色。
- 本样本没有灰盒物体，不会自动生成墙体、地板、颜色道具或可玩的关卡。房间轮廓只定义可编辑范围。
- MVMap 没有专门的通道类型；长条房间不能仅凭形状安全推断为通道，应在预览中由策划指定。

## 转换时需要明确的规则

1. 尺度：MVMap 的世界格和灰盒细格是不同单位，sub 可为 4/8/16。现有 Unity 工具已统一到房间细格；导入需明确“外部一格对应多少 Unity 格”。本样本没有 detail 内容，可以按外部一格=Unity 一格导入轮廓；若要保留未来 sub=8 的灰盒尺度，则每个外部世界格应展开为 8×8 个 Unity 格。不得直接沿用旧默认 16 或对不同房间使用不同整体比例。
2. 不连通房间：本次选择保留完整原形和原始 ID，导入房间标记 allowDisconnectedCells，支持多片同属一个区域；不静默删格或拆 ID。普通新建房间仍要求连通。
3. 灰盒坐标：MVMap detail.boxes 使用绝对细格坐标，不是房间局部坐标；转换时需减去转换后的房间原点，并映射 w/h、type 等字段。未知物体类型只做待映射占位，不猜预制体。
4. 门与锁：MVMap 门在格子边缘，且锁的多个 keyIds 是“任意一个满足”。不能直接转为本项目要求全部按钮按下的实体门。样本中为空，暂时没有接入压力。
5. 导入应创建独立新存档、提供只读预览与问题清单，不覆盖策划已有存档或当前 Scene；确认后再应用。
