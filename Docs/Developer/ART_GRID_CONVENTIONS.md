# 美术像素、网格与物体外观

本项目的场景美术基准为 **16 个美术有效像素 = 1 个关卡单元格**。素材的真实像素比例优先于占位模型的大小；物体碰撞、触发和存档占格不等于外观尺寸。UI 使用 Canvas 的参考分辨率体系，不套用场景网格换算。

## 换算与验证

原图编码像素可能是美术软件最近邻放大导出的结果，不能只读取文件宽高就认定其美术像素数。

```
有效像素 = 编码像素 / 已验证的导出倍率
显示格数 = 有效像素 / 16
显示世界尺寸 = 显示格数 × 当前关卡单元格世界尺寸
新物体占格 = 各轴显示格数向上取整，最少 1 格
```

导出倍率必须有证据：`GridArtworkMetrics.ExactExportScale` 对全图逐块比较 RGBA，同一 N×N 编码块必须完全同色；完全透明像素忽略无意义的 RGB。不能凭图形外观推测倍率。`tail.png` 已验证为严格 4× 最近邻导出，32 像素的重生点、24 像素的玩家、48 像素的平台均不是 2× 等整数导出。

统一 API 位于 `Project.ObjectArtwork.GridArtworkMetrics`，不依赖玩法组件。网格美术、贴花、关卡预览和运行时外观均使用它。

| API | 用途 |
| --- | --- |
| `PixelsPerCell` | 16 个有效像素/格的唯一基准 |
| `SourcePixelScale(Sprite/Texture2D)` | 当前已验证的 canonical tail 返回 4，其他返回 1 |
| `PixelsToCells(pixels, sourcePixelScale)` | 编码尺寸转换为显示格数 |
| `PixelsToWorld(pixels, cellWorldSize, sourcePixelScale)` | 转换为世界尺寸 |
| `PlacementFootprint(pixels, sourcePixelScale)` | 计算新放物体所需整数占格，消除浮点误差导致的额外一格 |
| `SpriteCells(sprite, sourcePixelScale)` | 精灵当前切片的自然格数 |
| `NaturalSpriteScale(sprite, parentScale, cellWorldSize, sourcePixelScale)` | 抵消现有导入 PPU 与父级非等比缩放，保持方形有效像素 |
| `ExactExportScale(colors, width, height)` | 只供导入/审计；不要每帧遍历纹理 |
| `ConfigurePixelSampling(block, sprite, cellWorldSize)` | TA 采样外观与 HSV 遮罩共用世界像素网格 |

`sourcePixelScale` 的默认值是 1。使用已有大图或共享素材库时，先读取确证倍率，不要再把 tail 的 64 编码像素误判为 4 格。新复制/重命名的特殊倍率素材应在笔刷中明确保留倍率，而非依赖文件名猜测。

透明留白属于帧的构图，不应把平台底部约 5 像素的可见条裁下来，再放大成 16 像素厚。平台保留完整 48×16 帧，可见条对齐支撑面。长平台沿长轴平铺，竖平台先旋转 90° 再按原像素尺寸重复；不压扁整张图片、也不改变旧平台的逻辑厚度。非矩形合并的覆盖格/空洞继续由 `LevelEditorMergedShape` 保留，不为显示方便补上不存在的格子。

小尖刺的完整一格帧里仅底部 4 像素可见，伤害三角按其 0.25 格高调整，底边仍是原格底 `-0.5`，四向通过原子物体旋转保持不变。该调整避免旧 0.75 格高碰撞在看不见的区域提前杀死玩家；不改变场景实例位置和所属房间。

## 左右侧面梯子

栏目提供“左连墙梯”和“右连墙梯”。“左/右”指墙相对梯子所在的一侧：左连墙梯从右边攀爬，右连墙梯从左边攀爬。当前共用已确认的梯档素材，左侧做镜像；未来可替换为独立正式侧梯图，不改变条目 ID 或存档。

旧 `LadderSide.prefab` 和 `mechanism-ladder-side` 保留为右连墙梯，旧 GUID 不变；新左连墙条目 `mechanism-ladder-side-left`。两者新放默认 1×1，已存在的长梯触发体和高度不被转换覆盖。

## TA 藤蔓与 HSV

TA 藤蔓不是 16 像素手绘图，原先把 92 像素宽序列帧直接拟合成 1.2 格、再把各帧不同高度拉到生长高度，会出现细于手绘美术的像素。`GridArtworkSampling.hlsl` 通过世界 XY 导数反推 UV，把取样点统一到 `cellWorldSize / 16` 的格心；UV 限制在当前图集帧内，不串到邻帧。

`WorldObjectSprite.shader` 和 `ColorObjectMask.shader` 引用同一采样函数。藤蔓传入 `_ArtworkPixelWorldSize`、`_ArtworkPixelUVRect`、`_ArtworkPixelTextureSize` 和当前帧纹理；主图与 HSV mask 必须同时更新。UV 在世界格心反算后再稳定到源图 texel 中心，避免刚好落到源像素边界时因浮点误差在同一世界像素内出现细线。两路共用 source-alpha 与 reveal-alpha 裁剪阈值，避免解锁透明交接时遮罩比外观大/小一圈。未开启该采样的普通精灵保留原始点采样，不受影响。

这是对 TA 序列渲染结果的统一像素化，不是把序列帧换回实时粒子，也不修改原序列文件。颜色解锁和 HSV/透明的共享管理器链路保持原样，不增加逐物体材质副本。

## 关卡预览与栏目

`Project.BlockFeatures.Editor.ObjectArtworkPlanningPreview.TryGet` 是关卡网格和道具栏目共用的只读二维美术入口。输入预制体、可选实例参数与占格，返回 `PlanningArtworkPreview`：`Texture`、`UV`、自然显示格数 `Cells`、`RotationDegrees`、`FlipX`、`Tile`；`Hidden` 表示用户显式关闭外观，不可因此回退为三维缩略图。

门、按钮、三色方块与钥匙、左右侧梯、平台、岩浆、黑曜石、基座、植物障碍、尖刺、重生点、弹性植物和告示牌均解析到实际二维资源。水的 `TryGetWaterTile(0/1/2)` 直接复用 `WaterPresentationSettings` 的正式水面、水中、水下图片及与运行时相同的 UV 裁切。网格根据相邻占用选切片，不把所有水都显示成一张水面。

藤蔓预览取 TA 的真实初始/长成序列帧，按当前高度一次缓存采样到 16 世界像素/格；不会实例化粒子，也不循环请求预制体相机截图。返回 `Texture + UV + Cells` 必须一起使用，以保持 1.2 格宽藤蔓边缘的部分像素和方形像素间距。缓存仅在素材变化、脚本重载时失效，平移与缩放不能重新读取文件或生成纹理。未交付二维素材的其他物体不应伪称已接入正式美术。

## 导入、存档与协作

- 图像 Point 过滤、关闭 MipMap、NPOT 不缩放、FullRect；max size 只取能完整保留原图的最小合适档位。正式像素美术不要依赖压缩消掉透明边缘。
- 使用切片的完整帧尺寸，不根据每帧不透明包围盒动态缩放，否则动画会呼吸式变大变小。
- 不把 prefab 根缩放或 collider 放大成新美术尺寸来修视觉。旧场景和存档中的实体占格、链接、位置是独立契约；默认新放规格可以更新，既有布局不得静默重排。
- 共享 prefab/材质不能因某个场景的美术铺绘被整体改写。场景实例的装饰、图层、覆盖应存在独立关卡美术存档中。
- 更改关卡需同时提交场景和对应规划存档；美术工作台的存档/素材库也应提交，不能只传生成结果。
- 法线图未来与颜色图必须使用相同切片、有效像素倍率、UV 和平铺规则，不额外拉伸。

## 回归验证

`ArtGridRefinementAudit.Run` 只能在 `Library/FlowRetirementProbe` 隔离工程运行，且不可使用 `-nographics`。它验证导出倍率、平台帧数/PPU、左右梯、旧碰撞保留、非矩形竖平台空洞、告示牌持久 SpriteID，并使用真实 GPU 对短/长藤蔓、透明交接、HSV 遮罩与图集边界做采样断言。报告写入 `Library/ArtGridRefinementResult.txt`，对照截图为 `Library/ArtGrid_*_color.png` 与 `*_mask.png`。

`WorldObjectArtworkSetup.BuildPlatformFrames()` 只重建两个平台帧组；`BuildSupplementArtwork()` 配置新图、保留其他工具已追加的装饰切片、更新物体图集，并幂等规范四向尖刺共享 Mesh 的可见判定高度，不保存打开的场景。生成图、其 `.meta`、`Objects.asset` 与四个 `Spike_*.asset` 必须成套同步。
