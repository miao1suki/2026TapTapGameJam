# 物体交互管理器

交互逻辑以具体物体为边界。颜色只保存为物体的基础属性，用于“受到颜色”、设置颜色、褪色和恢复等节点；颜色不会再拥有独立的交互图。

## 打开与同步

- 菜单入口：`Tools/2026TapTap/物体交互管理器`，也可从 `Tools/2026TapTap/交互/物体交互管理器`、`Window/2026TapTap/物体交互管理器` 或关卡规划原型入口打开。
- 如果 Unity 刚导入交互脚本后仍显示旧的命名空间/脚本错误，先让脚本重新编译（必要时重启 Unity），再打开上述菜单；交互定义和目录脚本已按 Unity 的单一 ScriptableObject 类型规则拆分。
- 窗口打开时自动同步交互目录和关卡编辑器栏目。当前红、蓝、绿方块会直接出现在左侧物体列表，不需要先选中 Hierarchy 物体。
- 关卡编辑器的方块栏目卡片在选中后提供“交互”按钮；道具卡片、道具编辑窗口和已放置物体 Inspector 也提供同一个入口。
- “同步关卡物体”会把栏目中的方块/道具导入交互目录，也会把交互目录中尚未出现在栏目里的预制体加入道具栏目。同一预制体始终复用同一个定义。
- 只有需要把新预制体加入目录时，才使用“导入选中物体”。

## 编辑流程

1. 在左侧选择物体定义；右侧显示该物体完整的连连看。
2. 用“＋ 节点”添加触发、条件、调度或效果节点，拖动端口建立顺序；选中节点后可删除。
3. 节点属性直接保存到 `InteractionObjectDefinition` 资产。运行时由 `InteractionManager` 编译成邻接表执行，因此 GraphView 不参与运行时性能路径。

## 当前三色方块图

三色方块的定义位于 `Assets/_Project/Content/Interactions/Definitions`：

- 红方块：玩家进入/停留/离开、物体触碰/停留入口，默认调用本物体的方法。
- 蓝方块：同样的接触入口；玩家进入/离开会通过图调用水体/游泳适配方法，解锁时由手动节点连接“恢复蓝色”节点。
- 绿方块：同样的接触入口；玩家进入/离开会通过图调用攀爬适配方法。

`ColorBlock` 只负责收集接触事件和提供物体方法，具体执行顺序由定义中的连线决定。策划可以在入口后继续连接受到颜色、受到物体、延迟、褪色、恢复、Timeline 或方法调用节点。

## 颜色钥匙与褪色

颜色钥匙的交互定义也属于物体图。红、蓝、绿钥匙定义分别把 `baseColorTypeId` 和手动恢复节点的颜色值设为 `red`、`blue`、`green`，因此在窗口中可以直接检查“手动 → 恢复颜色”的链路。钥匙的 Timeline 只负责相机演出；颜色解锁由 `ColorRuntimeService.Unlock` 先建立基础恢复状态，再触发钥匙图的 `Manual` 节点。这样即使演出被中断或图中缺少恢复节点，材质和蓝色水体也不会停留在褪色状态。

服务启动时会把颜色目录中的颜色初始化为褪色；方块注册时按当前运行实例的解锁状态同步。运行时锁回颜色会重新褪色，钥匙收集只会成功一次。交互图仍是策划扩展其他表现和方法调用的入口，不要在钥匙脚本中追加新的物体关系。

## 节点

- 触发：玩家进入/离开、物体触碰、物体停留、经过时间、手动执行。
- 条件：本物体、需要玩家、需要其他物体、受到颜色、受到物体。
- 调度与表现：延迟执行、褪色、恢复、播放 Timeline、调用方法、设置当前颜色、输出日志。

运行时单次事件最多处理 256 个节点；延迟使用协程；停留事件按帧去重。图中没有连线的节点不会被事件执行。

## 颜色系统边界

旧的 `ColorWorldManager`、`ColorInteractionRunner`、颜色交互图和颜色工作台已移除。`ColorRuntimeService` 只保留颜色解锁、当前颜色、颜色目录和水体视觉聚合；`HSVColorFadeManager` 只提供颜色层渐变服务。这些服务不提供策划交互入口，所有交互关系统一在物体交互图中编辑。
