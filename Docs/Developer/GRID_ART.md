# 网格美术编辑器（试用版）

## 现有素材与贴画工具评估

现有 SurfaceTiles 可以制作方块表面的地形美术：支持实际格数、多格瓦片、透明图叠加、贴边、微调、旋转翻转以及 Mesh/材质/PNG 持久化。它依赖 BoxCollider 的六面网格，不会新增玩法，不是 Unity 的投射 Decal。

实际制作仍有这些问题：

| 项目 | 当前情况与处理建议 |
|---|---|
| 新素材 | `Resources/26TAPTAP/场景背景/tail.png` 为 1408×704 透明底图集，包含黑白图案、边框、边角；部分图块本身有不透明黑底。已设置 Point、无 Mipmap、无压缩，但 Multiple 模式下切片列表为空，不能直接当瓦片库。规则示例只裁切新资源，不使用旧开发目录中的彩色库。 |
| 自动衔接 | 原贴画工具没有邻格规则。手工画墙要自己选边缘、外角和内角。多个方块的表面网格独立，跨模型、部分重叠模型和不同格尺寸不自动统一，内部隐藏面也不会自动剔除。 |
| 尺寸 | 切片必须明确“每格像素数”和透明留边是否属于占格。不能把动画板、整张装饰板全部按同一格压缩。帧动画仍应走各自物体表现组件。 |
| 背景 | 当前新资源中仅发现这一张场景图集，未发现独立远景/中景大图套件。索引是需求参考，不表示对应图片已制作。主菜单背景属于 UI，不默认用作关卡背景。 |
| 烘焙 | 原工具每个方块生成独立 Mesh、材质和六面合成 PNG，不等于整关批处理。大方块按每格像素数生成六面图集，单图上限8192；例如长墙很容易浪费大量像素。仍需保存 Scene/prefab 和全部依赖。物体缩放或布局改变后重新烘焙。 |
| 渲染 | Point/无 Mipmap 保留像素，但不能解决所有几何接缝、深度竞争、交叠面闪烁。大背景应单独分层，而不是用大量贴画方块堆背景。 |

建议保留 SurfaceTiles 负责真正的三维方块表面；GridArt 负责固定横版平面的美术墙面、背景与无碰撞装饰。不要把视觉背景兼作玩法碰撞。

## 开始使用

1. 从关卡编辑器点击 **网格美术**；或打开 `Tools/2026TapTap/关卡美术/网格美术编辑器`。
2. 新建该关卡的美术图资产。由关卡入口新建时继承当前格尺寸，默认一格对应房间/装配图一格；原点与场景世界零点一致，世界 Y 向上。入口将场景已应用的关卡物体轮廓作为黄色只读参考；它不读取尚未应用的草稿。
3. 选择瓦片库、图层和笔刷。左键绘制，右键擦除；勾选“框选区域”可批量操作。中键平移、滚轮缩放，“居中全部”找回全图。多格装饰框选按笔刷宽高铺开。
4. 每层独立设置显示、锁定、排序、颜色/透明度、Z 深度及视差。相同位置的多张图放到不同美术层。
5. 点击 **应用到当前场景**，再保存 Scene。每32×32格按源纹理分块保存 Mesh，复用源图、不烘焙整关巨大 PNG。运行时不重新切片或重建瓦片。
6. 修改笔刷、原图或画布后重新应用。画布撤销/重做不自动重新生成场景；烘焙产物更新不是资产撤销操作。

界面采用项目编辑器 UI 规范：UI Toolkit、原生可拖动/停靠/关闭窗口、可折叠设置、滚动侧栏、直接资源选择。各 Scene 记忆自己的美术图；每张美术图记忆画布视角。笔画与图层编辑记录到独立美术资产的 Undo，不改旧关卡编辑器的历史。

## 示例

菜单 `Tools/2026TapTap/关卡美术/打开美术测试场景`：

- 场景：`Assets/_Project/Development/GridArt/TileArtTrial/网格美术测试.unity`
- 美术图：同目录 `示例美术图.asset`
- 瓦片库：同目录 `素材与规则示例.asset`

“自动边角示意”为完整规则验证用的几何图，不是正式美术。“美术边框区域”与图案笔刷裁自 `tail.png`；原图不修改，内角未齐时明确提示并暂用中心图，不宣称素材完整。示例有三个图层，在 Play 中移动预览摄像机的 X/Y 可以观察背景不同速度，回到原位置无累计漂移。场景不含玩家、不改输入键位、不加入正式构建。

## 配置新素材

点击“切片导入”复用不规则瓦片工具；也可在 Unity Sprite Editor 切片。瓦片库 Inspector 提供图片选择与中文配置。

- **自动地形**：配置九宫格（左上/上边/右上、左边/中心/右边、左下/下边/右下）和四个内拐角。工具根据同笔刷的八邻格，将每格分成四个象限选图，支持洞、外凸角和内凹角。不同笔刷不自动相连。
- **装饰 / 大图**：配置 Sprite 与占格宽高；保持正确长宽比例，例如 192×128 图片在64像素/格标准下占3×2格。草边等透出到格外的图可另建装饰层；精细偏移仍优先用原 SurfaceTiles 工具。
- 使用独立、未打包的矩形 Sprite；本版不支持 SpriteAtlas 旋转/紧密打包。源图采用 Point、无 Mipmap、无压缩和足够的最大尺寸。

## 视差与边界

视差系数1表示普通世界背景，0表示相机移动时保持屏幕位置；远景通常0.2～0.4，中景0.5～0.8。组件只读摄像机位置，不参与相机控制权。每格像素数用于吸附背景位移，0关闭；与实际美术像素密度一致更稳定。

目前只处理固定 XY 横版平面的平移视差；没有自动循环大图、镜头缩放补偿、2D/3D转向背景重投影、区域选中搬移、按房间移动自动迁移美术、多地形过渡、规则随机变体或动画瓦片。先用有限背景并给镜头运动留足覆盖余量。这些是后续扩展项，不影响已有工具。

新美术默认不接颜色玩法、HSV 分层或 TA 像素化的标记；需要时由对应系统明确接入，不能把逻辑图层等同于 GameObject Layer。没有额外碰撞体，不会改变房间重置。

## 参考设计

- [Unity RuleTile](https://docs.unity3d.com/Packages/com.unity.2d.tilemap.extras@4.0/manual/RuleTile.html)：按邻格规则选择瓦片。适合后续更复杂的变体、动画和随机输出；本版没有安装该包。
- [Tiled Terrain Sets](https://doc.mapeditor.org/en/stable/manual/terrain/)：先标注边/角语义，再用地形笔刷。素材缺失时工具不能保证完整过渡。
- [Tiled Layers](https://doc.mapeditor.org/en/stable/manual/layers/)：美术图层、图片层和独立视差参数。
- [LDtk Auto Layers](https://ldtk.io/docs/general/auto-layers/)：逻辑格与自动美术层分离，适合后续从关卡墙体派生美术的架构。

本项目优先采用内置编辑器入口＋独立美术数据；需要复杂规则时扩展 RuleTile 或借鉴 LDtk，而不是立即让策划同时维护两个完整关卡编辑器。
