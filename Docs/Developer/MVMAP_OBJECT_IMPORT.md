# MVMap 物体试导入

测试场景：`Assets/_Project/Development/RoomLifecycleTests/MVMapImportTest.unity`。

配套存档：同目录 `MVMapObjects.planning.json`。场景也内嵌相同规划数据；在项目中打开测试 Scene 后，打开关卡编辑器即可编辑，或从存档面板读取这份规划 JSON。不要把原始 `.mvmap.json` 当作物体规划存档读取：普通 MVMap 导入仍是布局导入。

本版替换旧“主稿”试导入，使用新的 73 个区域、2450 格源图。正式 Gaming、Pick 和独立 RoomRespawnTest 不修改，测试 Scene 不加入正式构建。

这是待确认映射，不代表正式关卡设计。逐区域来源与对应预制体见 [映射报告](MVMAP_OBJECT_MAPPING.md)。该源图的名称全部是 Room 数字，未包含命名为“门”的特殊区域。

不规则区域按精确矩形拆分，不填满包围盒，不丢弃断开的岛。连续竖列藤蔓使用项目现有稳定组链与重置逻辑。大矩形水域生成一个整体实例，而非每格生成水体。

## 运行测试

- 场景自带 RuntimePlayer、跟随相机和起点重生点，直接 Play；使用既有输入，不加测试键位。
- 颜色物体开局未解锁。测试图没有源文件指定的颜色钥匙，可通过现有颜色管理器的运行态调试解锁颜色；不会凭空加入正式钥匙或解锁进度。
- 起点重生点是额外测试辅助，不是从源图推测出的物体；R 使用项目现有重生流程。
- 外部“房间”在本图代表物体，不是真实关卡房间。本版暂用一个整体重置区域，待策划另行提供房间/通道边界；不能据此验收多房间离区重置。
