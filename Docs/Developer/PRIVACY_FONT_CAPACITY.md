# 隐私政策字体容量核对

PC／Unity Editor 的政策正文由 `AndroidPrivacyPolicy` 使用统一 `Cubic_11 SDF` 显示；Android 政策窗口使用相同源字体的原生 TTF，因此 TMP 图集满了可能只影响 PC，不代表 Android 使用了另一套字体。截图中的“般”（U+822C）在源 TTF 中存在，当前政策全文的599个非空白独立字符也均在该源字体中。

2026-10-19 只读核对时，本地字体资产及已抓取的 main／Boss 相关远端引用仍为动态 2048×2048、未开启多图集；尚未发现另一位程序所述的4096修复已落盘。该字体存在用户未提交修改，整合窗口不会覆盖、代保存或重建它。若修改仍在主 Unity 内存，作者需在退出 Play 后检查字体 Inspector 的 Apply，保存字体资源并同步提交；不能只修改画质的纹理上限。改动应同时覆盖 Atlas Width、Atlas Height 以及匹配的材质／图集数据，遵循 TMP Inspector 的应用流程。

保持统一字体，不使用系统字体或 Arial 兜底。4096增加容量不等于源字体增加字符；以后大量新对白仍须复验，不能把一页正文通过当作无限容量保证。

## 隔离验证

只在停止运行的 `Library/FlowRetirementProbe` 工程执行 `Project.GameFlow.Editor.PrivacyFontCapacityAudit.Run`。入口创建相同源 TTF、采样字号、边距与渲染模式的临时字体，分别测试2048和4096；先加入共享菜单／暂停 UI 文字及已序列化字符，再加入完整政策。不会克隆并共享原始图集，不写原字体，不保存场景，结束自动退出 Unity。

结果写入隔离工程 `Library/PrivacyFontCapacityAudit.json`：包括两档缺字数量、字符与 Unicode 清单、真实UI文字及对象路径、独立记录的旧字符缓存、当前源字体配置、原文件 SHA256及前后字节一致性。缓存字符只产生容量压力，不因为曾存在缓存就自动成为界面要求；真实UI文字缺字不能忽略。报告分别给出政策容量、全部UI覆盖、源字体支持的UI覆盖结论，并把经FontEngine逐字符确认的源字体未支持字及其真实界面出处列入 `unsupportedActualUi`。本次容量目标／退出码通过要求4096覆盖源字体支持的真实UI和完整政策且原始字体文件未变；`uiCoveragePassed=false` 和未支持字警告仍须保留，不能说全部UI无缺字。2048仅作对照，不要求它一定失败。此入口是容量验证，不代表4096配置已经应用到生产字体或已通过双端打包。

首轮隔离结果：2048在菜单预热后政策缺246字，4096政策缺0，说明4096能解决本次正文容量问题。另外查出制作人员名单误写“臞日不再”（U+81DE），源TTF没有“臞”；它不是缓存噪声或政策内容。现已按用户确认，将正式主菜单、共享暂停及旧兼容菜单三处署名更正为“臾日不再”（首字U+81FE），保留其他名单、布局及字体引用。更正后已复跑审计，源字体支持全部采样UI文字，4096下真实UI及599政策字均无缺字，2048仍缺246政策字；原字体文件字节未变。作者4096图集配置仍待Apply保存交付，本窗口未代改字体资产。
