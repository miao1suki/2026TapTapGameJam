# 游戏 UI 美术接入

## 场景与组件

- 正式开始界面：`Assets/_Project/Scenes/Start/MainMenu.unity`。开始按钮仍通过 `StartMenuFlowBridge` 进入 Gaming，不恢复旧 Bootstrap 流程。
- 暂停和设置：`Assets/_Project/Content/UI/SharedGameUI.prefab`，由现有 `GameUiRouter` 与 `EscMenuController` 控制。不要另挂一套暂停输入。
- 颜色能力轮盘：玩家上的 `PlayerColorWheel` 管理输入、能力与选色，`PickWheelPrototype` 只显示外观。两份玩家预制体共用同一套美术，既有场景玩家在运行时沿用接线。

主菜单按美术示意图排布：开始、制作人员上下排列，设置与退出并排；制作人员按钮进入现有名单页。按钮按不透明内容的完整边界裁切，再加2像素透明余量保留黑描边；背景使用横向Repeat和负向UV滚动，使画面从左向右无缝循环，默认每秒移动0.025屏宽，可在开始菜单组件调整。原图不改动。素材不足的设置滑条与数值继续使用现有控件及统一 Cubic_11 字体。

菜单布局以320×180美术示意图为坐标基准，Canvas按1280×720参考分辨率等比例缩放，不使用固定最大缩放值。主页、制作人员、设置和存档页共用Canvas背景；子页面不再叠加独立背景，也不会重置滚动偏移。生成文件只保留在GameUI目录，禁止将其复制到上级目录产生重复GUID。

能力扇区顺序为红、绿、蓝，对应右下、上、左下。切分采用不透明像素连通区域识别，不按角度截断色块边缘。未解锁显示问号；悬停沿用硬切白色半透明与 DOTween 等比缩放，轴心是各扇区可见像素重心。暂停菜单直接以美术块作为完整按钮，替换占位扇区，关闭旧底盘表现，不把素材缩小叠到扇区里；按操作枚举绑定，旋转选项时按钮与文字保持正向。

暂停轮盘的W/S、上下方向键、手柄左摇杆及十字键使用统一上下导航方向；按住只切换一次，松开后可再次切换。确认沿用现有Jump/Submit映射。移动端可直接点击美术按钮选择并确认，或上下滑动切换选项，滑动不触发点击确认。手势只操作暂停UI，不改玩家输入和虚拟摇杆。

## 转盘表现基线

暂停表现：选中1.08倍、未选中0.94倍；所有选项均保持美术原色与完全不透明，不使用白化或半透明。切换0.6秒OutCubic，打开0.65秒OutQuart，均使用非缩放时间，快速切换打断前一次动画并从当前表现继续。图片中心距按245×缩放比例变化，保留原扇区以转盘中心放大产生的径向凸出，而非仅原地放大。使用默认UI材质，不创建独立高亮材质，不修改源图。菜单打开/关闭及子页面淡出仍保留，不属于选项白化效果。

颜色能力转盘仍按原有`PickWheelPrototype.SetSector`：选中缩小至0.84倍，0.24秒OutBack；恢复1倍，0.2秒OutCubic；白色半透明0.58硬切，仅缩放缓动。缩放轴心保持扇区可见像素重心；连续切换会停止旧Tween。没有添加暂停转盘的凸出或渐亮行为。

美术接入保留的外观差异：暂停占位几何/旧底盘替换为完整美术图片，图标保持正向；颜色能力红绿蓝扇区对应新美术位置并采用Point采样和离线切片，中心文字改为白色。打开、关闭、子页面过渡及业务调用沿用原实现。上下方向、Submit及触摸是单独确认的操作适配，不恢复旧方向或禁用移动端。

更换图片优先调整共享资源引用。`Project.Player.Editor.GameUiArtworkSetup.Build()` 是显式重建入口，会按当前原图坐标重切资源，并保存 MainMenu、StartMenuPrototype 与共享 UI 预制体；不会自动执行，也不会重存 Pick。源图排布改变时先修改切分坐标；不要在日常调参时反复运行。

## 水中玩家渲染

玩家像素材质改用 AlphaTest 队列、透明像素裁剪和深度写入，并提供水下底图采集所需的基础纹理/颜色兼容属性。透明留白不会挡水，角色实像素先进入底图，再由水面进行混合；没有通过提高排序把整个玩家强制贴到水前面。玩家层级、碰撞、游泳与 TA 水材质不变。

隔离项目使用真实 PC URP 管线渲染对比：旧透明玩家在水下可辨像素为 0；修复后可辨像素为 5223，其中 4039 像素受水效果混合。截图及记录在 `Library/FlowRetirementProbe/Library`。主菜单、设置、暂停和轮盘已做 GPU 截图检查；当前窗口手感与实机打包仍需测试。
