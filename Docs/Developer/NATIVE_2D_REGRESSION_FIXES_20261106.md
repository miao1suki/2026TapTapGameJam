# 原生 2D 回归修复与验收

日期：2026-11-06。分支：`codex/2d-long-term-migration`，修复基线 `0921002`，Unity 6000.3.12f1。本次不合入 main。

## Scene 透视预览残留与距离相关错误

Renderer2D 不执行普通 3D 渲染器的 Skybox 清屏流程；SceneView 仍可能带 Skybox/Nothing 状态。旧水下捕获还在 Renderer2D 所有场景绘制之前读取 activeColor/activeDepth，这时附件内容尚未建立。星空临时平面沿用上一台正交相机的位置，在透视预览中也可能出现不正确的背景。

修复：仅 Editor 的 `Native2DScenePreview` 在 URP 建立相机数据前明确使用 SolidColor 清屏。旧水下捕获改为自己清屏的独立 unlit 绘制，只在存在旧水实例时执行；不再复制尚未绘制的相机附件。星空平面仅对正交相机显示。玩法相机保持原生 2D，没有重新引入透视玩法。

边界：隔离工程未稳定复现用户截图中整张地图重复成条带的完全相同画面。因此这里区分“确认并修复了无效采样/清屏路径”与“原始截图全部成因已证明”。GPU 回归覆盖平移到空白处后旧颜色/深度不残留；若仍出现截图中的特定条带，应继续采集对应 SceneView 图形帧。

## 水体折射

已用真正的 Renderer2D 渐变背景夹具复现核心问题：旧 Shader 调用 `GetNormalizedScreenSpaceUV`，依赖当前自定义路径未初始化的 `_ScaleBiasRt`，导致纵坐标落到纹理顶行；顶行被拉伸到整片水中。零折射时本应与原图相同，旧实现仍有 50400/76800 个像素错误。相机位置、距离改变会改变被拉伸的内容，与用户反馈相符。

另外，旧噪波按每个水物体的局部 UV 重启，独立水片之间不连续；位移直接用屏幕比例表示，缩放后可对应很多世界格。Scene 编辑态的折射请求也未可靠注册。

修复如下：

- 同相机附件直接按 `SV_POSITION.xy / _ScaledScreenParams.xy` 取样，不依赖 `_ScaleBiasRt`。
- 噪波连续使用世界 XY；按世界格尺寸投影偏移，每轴最多偏移 4 个屏幕像素。
- 同相机先复制完成的透明场景，再生成水足迹并绘制折射；位移后落到干区时退回原像素，避免从墙/空气拉入条纹。
- 足迹与当前深度保持相同 MSAA；采样纹理在执行阶段绑定，避免跨相机沿用旧纹理。
- 折射请求组件支持编辑态，只对当前相机可见水面申请；原美术像素与地图几何不缩放、不重刷。

## 搬运放置容差

旧方向射线固定长 1.1 格，会把合法落点远侧的贴墙当成“玩家与落点之间的墙”。原生 Box2D 的 Overlap 还可能返回留有真实间隙的大型缩放地板；候选命中不等于内部穿透。玩家在一格夹墙间让位时，贴地接触也会误阻挡水平运动。

统一接触皮肤默认 0.02 格，按原生接触设置最多为 0.04 格。只内缩落点边界，内部薄障碍仍阻挡；方向射线取 1.1 格与到落点中心距离的较小值，完整落点体积独立检查。水平让位忽略地板/顶面的切向接触，终点继续验证真实胶囊穿透。预览线改用现有 Renderer2D 可绘制材质。

覆盖贴墙、1.5% 微小接触、真实穿透、途中 1% 薄墙、落点内部薄障碍、左右镜像让位、取消、动画途中被占等 50 项专项。没有允许穿墙、跨区放置或改变玩家逻辑占格。

## 获取颜色时的卡顿

在真实 Gaming 中查到 1216 个水体表现来源。旧路径激活后为全图水建模；每格邻接/归属查询反复遍历全图来源，远处任一水变化又使所有网格失效。此外有重复 Collider/材质设置、MPB 分配、岩浆美术创建和不可见藤蔓序列更新。

处理方式：

- 全局颜色解锁、碰撞和功能仍同步；只延后不在主相机范围内的表现工作，视野外扩 2 格预热，进入视野补齐当前状态。
- 首次中性外观渐变期间，水网格初建按每帧 6ms 预算分批；单个网格不可抢占，首次缓存建立仍可能超过预算。读档恢复、真实外观已经交接和动态水变化不等待该预算。
- 水邻接采用 Scene/格尺寸空间索引；本地拓扑签名避免远处变化重建当前水池。
- 蒸汽点击查询直接读取实时体积；禁用后重新启用必须补建网格，避免表现优化制造房间恢复缺失。
- 岩浆美术延迟创建；藤蔓的逻辑时间、目标高度和碰撞照常推进，只跳过不可见序列显示更新。复用 MPB，材质渐变仍由统一服务维护。

同机隔离 CPU 采样（真实 Gaming，非 FPS 保证）：

| 项目 | 原实现 | 修复后 |
| --- | ---: | ---: |
| 蓝色解锁调用 | 68.739ms | 59.489ms |
| 解锁后水体表现批次 | 2604.632ms，全图 1216 来源、2415 个生成 Renderer | 26.253ms，首批 1/1216 来源 |

后者约减少 99% 的初次批次开销，剩余工作被视野过滤和分帧预热。它不代表完整帧只花 26ms，也不代表所有设备稳定 60FPS；同步逻辑、首次缓存建立仍有成本。后续优化须继续保证看不见的水、岩浆和藤蔓具有正确玩法状态。
