# 收集品初始化与手机修复交付

## 收集品

- 修复新轮重置逐个激活物品时，Changed 监听者查询进度，将其他物品尚未清理的旧收集状态重新填回目录的问题。现在先清理全部物品状态，再激活，最后只通知一次。
- 修复未执行 Awake 的冷物品先恢复/重置时，初始缩放尚未捕获、被重置成零的问题。
- 读档恢复不重复发送收集成就；当前地图暂未实例化的已收集稳定 ID 不再在自动保存时被丢弃。
- 收集品图片放在格内，正确被隐藏方块的不透明表面遮住；物理根节点与拾取 Trigger 不移动，Scene 预览与运行一致。
- 不删除或重建玩家存档，不以运行时实例 ID 替代作者稳定 ID，不改最新 main 的 Gaming 布局。
- 最新 main `5998455` 的正式 Gaming 还复现了另一条直接原因：普通收集品保存成了“根对象关闭、刚体运动学、全部 Collider 关闭”的已收集运行态。读档旧流程只隐藏已收集 ID，未恢复其余物品，导致未收集物品也无法拾取。现在读档先两阶段准备普通收集品，再应用存档 ID；仅对上述完整挂起状态恢复标准物理基线，房间重置也不再恢复错误的禁用标记。已收集物品仍隐藏，演出排除物不参与。

## 隔离验证

Unity 6000.3.12f1，静音隔离工程 `Library/FlowRetirementProbe`，独立产品名与 Library 测试存档目录；不操作主 Unity 或真实存档。

- `CollectiblePersistenceAudit.Run`：57 项真实物理/生命周期断言通过，包括 Trigger/飞行结算、离区、重生、新轮通知重入、冷恢复、稳定 ID 和隐藏块深度。
- 修复前后对照：将隔离工程三份收集品运行时代码还原为 origin/main 58c6df7，在同一测试中稳定失败于“new run cannot re-register old collected IDs”；修复后完整通过。对照仅改隔离副本，不改作者工程或原存档。
- `CollectibleFormalSaveAudit.Run`：采用 origin/main 58c6df7 的正式 Gaming，实际启动并加载测试存档，已收集物品隐藏；未收集物品实际碰撞/飞行拾取，自动存档写入，房间重置后进度保留。
- 同一正式测试升级到 `5998455` 后先复现“全部普通未收集物品 inactive”，加入读档双向校对后再验证真实拾取、存档及未收集物品离房仍可拾取。Gaming、planning、正式关卡 JSON 原样保留远端版本，不手工改地图来绕过问题。
- 最终版本57项收集品断言再次通过（包含完整挂起快照夹具）；手机曲柄专项18项通过，手机布局与输入专项32项EditMode测试通过（0失败、0跳过）。

这些结果确认初始化路径存在缺陷并已覆盖修复；未取得策划当时的原始存档及完整操作录像，不能断言其所有“清零”反馈均只有同一原因。地图变动后作者 ID 改变也需单独排查。
