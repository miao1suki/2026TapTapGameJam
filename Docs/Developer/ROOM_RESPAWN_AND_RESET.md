# 房间、通道与重生

## 测试入口

- `Assets/_Project/Development/RoomLifecycleTests/MVMapImportTest.unity`：主稿的 65 个区域、17,281 格。打开关卡编辑器可读取场景内地图；Scene 显示区域边界。仅首个区域增加小段测试地面、玩家和重生点，不将规划区域填成实心方块。
- `Assets/_Project/Development/RoomLifecycleTests/RoomRespawnTest.unity`：两间房、一个通道、四个重生点，含搬运物、水体、预置藤蔓、钥匙及两按钮门，可直接 Play。未加入正式构建。

现有场景在关卡编辑器点击一次“应用到场景”，再保存 Scene，可写入区域及重置组件。没有世界图区域的旧场景不能仅凭物体位置推测房间；不修改 Pick 的未提交布局。

## 放置与触发

道具栏目选择“重生点”，放在房间或通道中；一个区域可放多个。应用时自动绑定稳定区域 ID。参数模式可设置激活半径、复活高度及安全查找半径，单位为格；Scene 绿色虚线圆显示激活范围。

进入范围后设为当前重生点。重新进入已用过的点也更新绑定，与编号大小无关。未触碰时沿用已保存锚点或玩家出生位置作为后备。

默认激活半径为 1.5 格，可在参数模式或 Inspector 调整。测试外观仅当前绑定点为青色；绑定新点后，原点恢复非当前材质。离开虚线范围不取消绑定。表现设置中的“非当前材质 / 当前重生点材质”可替换为正式美术。

R 使用已有输入动作。存活时也能重生，暂停和非搬运演出控制锁期间不响应。带管理器的场景默认死亡后自动重生，可在 Inspector 关闭。优先寻找安全地面，避免复活到岩浆或实体内部。

## Boss 关卡重生点

重生点 Inspector 的“关卡类型”可开启“是否为 Boss 关卡重生点”。开启后直接在该重生点组件上设置：

- 复活后 Boss 血量：玩家完成复活时把全局唯一 `Boss` 的状态设置为该血量。
- Boss 横向位置：相对重生点的 X 偏移；Y 自动与重生点相同。

在关卡编辑器参数窗口点击“生成 Boss 复活标记”，会在当前房间规划中创建一个与重生点按 ID 连接的标记格，效果类似门生成按钮。该标记格只能沿 X 拖动，Y 始终与父重生点一致；场景应用时不会生成额外实体。

场景中同时维护一个无 Collider、无 Renderer 的 `Boss Respawn Marker` 子物体。选中它后，Scene 手柄也只允许沿 X 拖动。规划标记或 Scene 附属物被删除后都会自动补建，业务数据仍保存在重生点本身。

该设置用于防止 Boss 在玩家复活后已经跑到玩家前方。Boss 后生成也能生效：复活时若 Boss 还不存在，重生点会进入“等待 Boss 生成”，Timeline 生成并启用 Boss 后自动应用。Inspector 的“运行时调试”会显示待应用状态、最近检测血量、坐标和是否一致，也可点“模拟应用 Boss 血量与位置”。

Boss 战斗 HUD 的名字由 BossController 的“Boss 名字”设置。屏幕左侧监控窗与血条同时开启；监控窗从中心展开，Boss 死亡后默认延迟 5 秒再与血条一起倒放收起。

## 重置规则

复活表现可由开发者设置为常规或带加载背景的慢速转场，默认常规；不影响下列恢复规则。调试方法见 [复活表现](PLAYER_RESPAWN.md)。

区域按世界图实际占格判断，不使用包围盒，空洞不算进房间；不连通的外部片段可同属一个 ID。房间和通道是独立区域。

离开时仅重置刚离开的区域。重生时重置来源区域和重生点区域，相同时只执行一次。

| 对象 | 重置结果 |
| --- | --- |
| 门、保持模式按钮、门提示、锚点 | 保留状态与关联 |
| 持续压住模式按钮 | 清除按下状态；对应门取消持续信号，其他保持按钮进度不清空 |
| 已拾取或正在收集的钥匙 | 不恢复、不重复结算 |
| 颜色解锁 | 保留，不重新播放钥匙演出或全屏解锁过渡 |
| 已解锁颜色物体 | 回到布置位置及刚解锁的基础行为，仍解锁 |
| 未解锁颜色物体 | 保持未解锁 |
| 万能方块 | 清除临时染色，回布置位置 |
| 烧毁植物、反应替换物体 | 恢复原对象，清理临时替代物 |
| 藤蔓 | 保留预置链接及初始长度，清除燃烧和运行时新增节段 |
| 搬运、移动物体 | 停止本次搬运，恢复作者位置、旋转、缩放及碰撞 |

“布置位置”不是上一次拿起或落地的位置。三色接触方块和可搬运方块不能带出自己的布置区域：跨区放下被拒绝，物体根中心进入其他房间/通道或区域外会立即回位复原。玩家离开区域时取消携带并重置来源区域的全部可恢复物体。离开区域不会清零玩家移动速度。

## MVMap

当前独立测试 Scene 已更换为新源图的物体试导入，配套共享规划存档与临时映射说明见 [MVMAP_OBJECT_IMPORT.md](MVMAP_OBJECT_IMPORT.md)。下面的导入按钮仍是布局模式，不会自动把颜色猜成物体。

存档面板“导入 JSON 为新存档”可选择 `.mvmap.json`。支持 v1 区域轮廓、名称、ID、颜色、区域归属 ID 和备注，外部一格对应房间图一格；保留负坐标和不连通片段。

仅导入布局，不转换灰盒详情、不推测长条区域为通道。含门/锁/钥匙规则的外部文件拒绝导入，避免错误接入不同的解锁语义。未来 detail/sub 需要另外定义物体类型和细分尺度映射。

不改写外部源文件。新 Scene 内嵌规划 JSON 可随 Git 分享，首次打开不依赖某台电脑的 EditorPrefs；已有本机工作区优先，以免覆盖未完成编辑。
