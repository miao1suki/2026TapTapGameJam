# 编辑器窗口卡顿实测与修复

仅修改 Editor，不改变关卡、美术资产、运行时物理或构建质量。Unity 6000.3.12f1 / D3D11，在隔离工程加载正式 Gaming、4343 条规划对象和3972格美术；实际创建 SceneView、PlanningCanvas、ArtCanvas，开启 Editor CPU Profiler，连续平移并采集窗口更新间隔。每阶段72次，前12次预热不计。

## 根因

- `ArtworkScenePreview.Flush` 在全局层级通知后重复探测所有对象组件；缺失组件查询产生大量临时分配，且无变化也请求 Scene 重绘。异常布局复现约270ms持续更新间隔，其中一次 Flush 约247ms，59轮出现838万次缺失组件查询。现缓存正负分类和组件数量、限定属性变更范围，只在实际几何改变时重绘；原生新增/删除组件仍能被发现。
- `SurfaceTilePreviewRefresh` 也不再因空队列要求所有 Scene 重绘，避免编辑器工具辅助对象的通知形成空刷新循环。
- 关卡画布除白块外，水、藤蔓、机关等 Image 原来在每次平移时改写数千个布局属性。现在使用固定比例几何和父层变换，编辑或资源变化才失效重建；显示开关、选房、合并选择、拖动物体仍更新。悬浮放置提示独立于保留几何。
- 连线每帧重复扫描全表并查询预制体组件/序列化参数；现在缓存筛选后的机关与ID索引、道具条目及平台路径。装配原点也不再为每个对象扫描房间全部占格。超长按钮虚线沿视口裁切。
- 重生点圆环32次单线提交改为一次批量提交；Scene放置器网格仅在Repaint提交，不在Layout重复生成。

## 同机结果

下表为实际 Editor 更新间隔中位数／P95，毫秒。包括 Profiler 开销及该布局其他窗口工作，不等同独立包帧率，不承诺所有电脑恒定帧率。

| 窗口 | 修复前 | 修复后 |
| --- | --- | --- |
| Scene近景（正常路径） | 7.10 / 7.86 | 7.12 / 10.70 |
| Scene远景（正常路径） | 14.28 / 15.22 | 11.79 / 16.88 |
| 关卡装配图 | 102.06 / 120.16 | 12.11 / 17.60 |
| 关卡细节图 | 18.77 / 22.28 | 4.15 / 7.96 |
| 美术远景，含关卡参考 | 2.57 / 3.42 | 2.09 / 2.95 |
| 美术近景，含关卡参考 | 1.79 / 2.47 | 1.86 / 13.51 |
| Scene同时开关卡窗口 | 14.78 / 17.27 | 11.67 / 16.48 |

Scene异常持续阻塞路径修复后未再出现。正常Scene近景及美术近景没有显著提速，偶发后台窗口工作仍可产生尖峰；不把这些统计包装成全面恒定提速。美术画布本轮未发现同量级热点，保留全部绘制与关卡参考，不靠隐藏内容提速。

装配平移本身更新中位数49.59→0.36ms。12000未合并白块仍使用原批次；新缓存覆盖原生美术，而不是只针对已合并关卡。

## 使用和验证

无需开启“低质量模式”。已有窗口经脚本重编译后可关闭重开；不要为刷新工具保存覆盖未确认的场景。修改、Undo、资源刷新仍走现有文档通知，不能绕过通知直接修改后期待缓存自动识别。

`EditorFlowPerformanceAudit.Run` 只允许隔离 `Library/FlowRetirementProbe`，以非batch Editor运行，输出日志 `EDITOR_FLOW_PERF` 和 `EDITOR_HOT`；后者为包含子调用的耗时，不能相加当作总帧。原始本机日志为该工程 `Logs/EditorFlowBaseline2.log`、`EditorFlowFixed3.log`、`EditorFlowFinal.log`，不提交Library。

另通过：12000独立白块8项、原生美术保留17项、世界图开关16项、1024独立美术对象22项（100次无关层级通知不重建/不请求重绘、原生组件增删、选取和裁切）。`PlanningNativePreviewRenderAudit.Run`在隔离工程进入空场景Play以推进真实GPU帧，验证4个平移/缩放视图：保留几何和强制重建图像逐像素一致，且不同视图图像确实改变；不使用Edit模式冻结RenderTexture的假阳性结果。测试未保存主Unity场景，未重新打包。实际作者复杂操作仍需持续复测；首次资源加载、编译及外部插件不是本次窗口热路径指标。
