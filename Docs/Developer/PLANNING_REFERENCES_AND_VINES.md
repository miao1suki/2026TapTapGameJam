# 规划存档与藤蔓组链

道具参数中的资源引用以 Unity GlobalObjectId（资产 GUID 与本地文件 ID）保存。临时 instanceID 只适合当前编辑器进程，不能作为 JSON 存档或跨电脑协作的持久标识。

此规则适用于所有道具，而不只是藤蔓：水体、蒸汽/粒子预制体、材质、Mesh、字体、Timeline 资源等均走同一参数存档路径。流向枚举、速度、尺寸和其他数值不依赖对象 ID。Unity 原生场景、预制体和 ScriptableObject 的 GUID/fileID 引用本身没有此问题；运行时缓存字典使用 GetInstanceID 也没有此问题。

新参数与新导出图保存持久引用。旧 JSON 的临时引用不能可靠恢复到原自定义资源，加载时不信任旧数字，不用空引用覆盖预制体默认资源；需要自行指定的资源请在参数模式重新选择并保存一次。显式清空和资源丢失分开处理。场景内对象绑定不跨实例复制。

同一房间内，同列、同母预制体、同格尺寸的连续单格藤蔓，应用到场景时最下方保留母根，上方生成 Green_LadderSon。保存场景前记录母根节段数组和每个节段的母根为 prefab override；增量应用结束后重新校验最终层级，不保留指向 staging 的链接。运行时启用时按直属节段层级恢复所有权，不执行逐帧全场景扫描。单独一格母根保留自己的最大生长参数。

已失链的旧生成物请从所属规划图重新“应用到场景”；不要手动把所有段设置为母根，也不要清空规划数据。手动场景物不参与跨房间组链。

## 定向水流

Blue_WaterWay 使用 DirectionalCurrentFeature，默认向右，推搡速度 4。蓝色解锁后，接触玩家时进入游泳并按物体局部左右方向写入玩家的来源速度；方向经 Transform 转换、投影到 XY 平面后归一化。退出或重置时清除此来源。玩家控制器在 FixedUpdate 合并各水流来源并应用到 Rigidbody，功能组件不直接写玩家 Transform。

当前只有左右两个流向选项，不是自由方向箭头。旋转物体会影响推力的世界方向；方向完全指向 Z 时不产生新的 XY 推力。水体波纹/反射表现独立接入 TA 的 InteractiveWater，当前流向参数不驱动水 Shader 的流向。
