# 藤蔓生长托举

普通藤蔓仍由蓝色交互/水接触调用 `ClimbableVineFeature.GrowTo`；不是绿色接触方块自身伸长的改写。藤蔓顶部有动态、启用重力的实体方块时，先检查整次上移一格的路径，再逐物理步托起方块，最后补全这一格藤蔓实体。没有载荷时保留原有生长设置；“瞬间长完”遇载荷也改为分步托举，至少0.1秒/格，避免瞬移和穿墙。

## 规则与边界

- 接触必须在生长顶面，不从侧面推走方块。普通重力刚体、三色接触方块和启用重力的基座均可承载；静态墙、运动学物体和关闭重力的基座仍是障碍。不会更改基座实例的作者重力参数。
- 向上检查整组接触堆叠及载人头顶空间；有墙、植物障碍、平台、无重力物体、查询溢出或房间边界限制时，保守停止，不推穿障碍。生长期间逐物理步重查新进入的障碍。
- 载人走既有 `PlayerController.QueuePlatformDelta`，不把玩家设为子节点，不直接写玩家Transform。玩家离开支撑、跳起、死亡或被其他演出锁定时不再跟随。
- 颜色反应不取消：红色接触方块仍会烧藤蔓；蓝色接触方块仍会触发生长。红块被烧掉脚下藤蔓不是托举失败。物理夹具部分案例暂挂起接触反应以隔离运动控制器，另有不挂起反应的蓝块生长、红块燃烧检查。

## 控制所有权

`VineGrowthLift` 只在一次有载荷生长期间持有短时刚体租约，缓存约束/重力并用 `Rigidbody.MovePosition` 分步上移。`ContactCubeMotion` 和 `MechanismBaseFeature` 在租约期间不重复写同一个刚体；移动载荷保留与玩家的实体碰撞。完成、受阻、燃烧、禁用和房间重置都释放租约并恢复重力/约束，不永久冻结方块。

搬运和绿钩子开始接管时调用 `VineGrowthLift.Cancel(body)`，先归还原物理状态，再由原系统接管，不把“托举期间临时关闭重力”误记为方块永久属性。不改原来的搬运、信号、颜色解锁与房间重置接口。

新增运动系统如需接管已有刚体，也应先Cancel；不要与托举并行写位姿。检测使用有限的NonAlloc缓冲，仅在生长请求与活动托举期间执行，不每帧扫描全场景。

## 隔离回归

`TimelineVineLiftAudit.Run` 仅允许 `-noaudio` 的 `Library/FlowRetirementProbe` 项目，使用真实自动FixedUpdate/协程/PhysX和标准玩家，不仅直接调用私有方法。覆盖三色块运动控制、普通载荷、重力/无重力基座、堆叠、载人、天花板、途中新增阻挡、搬运/钩子接管、房间重置与燃烧；另检查隐藏Timeline触发器。不能在作者当前场景执行，不代替安卓实机和完整关卡手感验收。

本轮79项真实物理检查、83项既有玩法、324项绿绳物理、37项真实输入更新、232项EditMode均通过。连续两格托举和玩家实际跳跃亦覆盖；图标与画布另有12项附着预览和51项既有编辑交互回归。
