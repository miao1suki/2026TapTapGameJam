# Scene 编辑态预览开销

Scene 视图平移和框选会触发编辑器独有的 Layout、Repaint 与 Gizmo 回调；Game 或独立包流畅，并不意味着这些编辑回调没有额外开销。白块合并只能减少实体数量，不能替代编辑绘制链路的优化。

`ArtworkScenePreview` 的当前处理：

- Layout 选取先做世界射线与缓存包围盒相交，只有候选物体才进入局部四边形三角形相交。避免对视野内每块水、藤蔓和道具逐四边形投影四个 GUI 点。保留作者实例选取、隐藏物体排除及变换手柄优先权。
- Repaint 单次遍历生成水／其他物体的复用绘制列表，Stage 查询移出逐物体循环，视口外物体不做后续原生可见性查询。连续相同材质只绑定一次 Pass；不重排透明绘制次序、不隐藏实际美术。
- 非水物体或不相关属性变更不重建水域占格。物体／水的实际改变仍通过原事件队列更新缓存，不写入 Scene，也不重建玩法对象。
- 方块足迹从 BoxCollider 的局部中心／尺寸经当前 Transform 矩阵计算，不再读尚未同步物理世界的 `Collider.bounds`。隔离复现中作者位置已到(-16,-16)，native碰撞包围盒仍在(0,0)；原缓存因此会把图片和选取放错。修复不需要全场景 `Physics.SyncTransforms`，不因编辑预览额外同步所有物理物体。
- 平台和门的长连接线在调用 `Handles.DrawDottedLine` 前裁到相机六面视锥。两端都在视口外但中间穿过视口的线仍显示；完全在外的线跳过。平台端点、重生点与 Timeline 图标仅在可见时绘制，Gizmo 非 Repaint 事件不重复提交几何。

## 隔离验证

`ScenePreviewPerformanceAudit.Run` 只能在 `Library/FlowRetirementProbe` 调用。它创建 1024 个**未合并**标准蓝块，验证多点选取、Scene 隐藏、空白选取及十万格长连接的内外／近远裁切，并记录 200 次 CPU 选取耗时。结果为 `Library/ScenePreviewPerformanceAudit.txt`。

该 CPU 审计不等同于真实 Scene 总帧率；需另在完整 Gaming 的 Scene 视口平移／缩放、进入退出 Play、隐藏／显示、选择物体和变换手柄验收。不得将静态热点修正表述为已经证明所有编辑器卡顿来自同一个原因。未修改 URP、运行时游戏性能参数或构建质量。

2026-10-20隔离Unity6000.3.12f1编译与18项断言通过；1024独立蓝块200次CPU选取8.63ms，平均0.043ms。刻意未同步物理变换，确认使用当前作者位置而非原生滞后包围盒。尚未执行真实用户Scene拖动总帧率验收。
