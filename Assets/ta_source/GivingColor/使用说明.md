# 三色染色覆盖效果使用说明

## 1. 功能边界

本模块只提供成功染色后的短暂视觉反馈。玩家能力球的获取、颜色解锁、接色判定、玩法反应和物体最终颜色仍由原有玩法系统负责。本模块不调用能力解锁接口，也不修改目标物体的原 Renderer 或原材质。

运行时在原物体表面绘制一个临时覆盖层。动画完成后，覆盖层在 0.45 秒内渐隐，露出原玩法逻辑已经设置好的外观。房间颜色重置、目标停用或销毁时，临时覆盖层会被清理。

## 2. 组件清单与挂载位置

| 组件/资源 | 放置位置 | 是否需要手动添加 | 用途 |
|---|---|---:|---|
| `GivingColorEffectController` | 可放在场景中任意一个常驻活动对象上；推荐与玩家的 `PlayerColorWheel`、`PlayerInteractionSensor` 放在同一个玩家根对象上 | 否。场景加载后会自动查找玩家颜色轮盘并创建隐藏的运行时监听器。只有要手动调整控制器参数时才需要添加 | 监听原有的“染色成功”事件，并按颜色启动覆盖效果 |
| `GivingColorEffectTarget` | 放在需要允许播放覆盖效果的接色目标 GameObject 上；该物体或其子物体需有受支持的 `SpriteRenderer` 或 `MeshRenderer` | 通常不需要。成功染色后，控制器会为符合条件的目标运行时添加 | 效果目标标记及临时覆盖层的生命周期管理。不是玩法接色接口，不负责改变物体颜色 |
| `GivingColorTestReceiver` | 仅用于测试的目标 GameObject 上；同一物体需有可见 Renderer，并处在玩家交互范围内 | 仅在需要用普通测试物体验证效果时手动添加 | 测试接色接口。颜色已解锁时返回成功，让控制器播放效果；不保存颜色，也不改变目标的原外观 |
| `GivingColorDye.mat` | `Assets/ta_source/GivingColor/Resources/GivingColorDye.mat` | 无需挂载 | 所有效果共享的运行时参数来源。直接在该材质 Inspector 调节像素化、三色速度与噪波等 Shader 参数 |

**重要：**`GivingColorEffectTarget` 不应代替 `IColorApplicationTarget`。正式玩法物体仍由原组件实现接色判定和玩法变化；只有确认该物体需要视觉覆盖效果时，才让它成为效果目标。对于原有普通接色物，如果需要启用效果，可以在其预制体/独立测试对象上预先添加 `GivingColorEffectTarget`。不要把它加到水体、植物或不应播放效果的反应目标上。

## 3. 推荐接入方式

### 方式 A：沿用自动监听

适用于已有玩家染色流程的场景：

1. 场景中正常存在原有玩家对象，以及玩家的 `PlayerColorWheel` 和 `PlayerInteractionSensor`。
2. 不用改场景，也不用手动添加 `GivingColorEffectController`。运行时监听器会自动创建，并从玩家对象查找上述组件。
3. 通过原有流程获得颜色能力并选择颜色，然后像平常一样点击目标。
4. 只有原有接色逻辑报告成功且目标属于允许播放效果的类型时，覆盖效果才播放。

自动创建的监听器使用 Shader 中的默认配置和控制器代码里的默认时长。需要调整这些控制器参数时，使用方式 B。

### 方式 B：在独立测试场景手动配置控制器

1. 在自己的测试场景中创建或选中一个常驻活动 GameObject；推荐使用玩家根对象。
2. 添加 `GivingColorEffectController`。不要创建第二个控制器；同一场景只保留一个。
3. Inspector 中将 `玩家颜色轮盘` 指向玩家的 `PlayerColorWheel`，将 `玩家交互传感器` 指向同一玩家上的 `PlayerInteractionSensor`。留空时组件会尝试自动查找。
4. `覆盖 Shader` 可以留空，组件会使用 `GivingColorDye.mat` 中的 Shader。
5. 按需调整控制器的三色基础时长、高级效果参数；材质上的速度倍数会再缩放基础时长。

手动配置控制器只用于视觉接入和参数配置，不要改动玩家开局获得三种能力的流程，也不要通过这个组件授予或保存颜色能力。

### 方式 C：给测试物体提供可点击的成功接色接口

`GivingColorTestReceiver` 仅用于独立测试：

1. 选中一个带可见 Sprite 或 Mesh Renderer 的测试物体。
2. 确认原有 `ColorRuntimeService` 可用，并且测试时选择的颜色已经按原流程解锁。
3. 在该物体上添加 `GivingColorTestReceiver`。
4. Play Mode 中选择颜色并在交互范围内点击它。接收器返回成功后，染色控制器会播放该颜色的覆盖效果。

该接收器不修改物体的玩法颜色，因此效果结束后物体会恢复显示其原外观。它不是正式关卡的染色逻辑，也不要为了测试改动能力球获取流程。

## 4. 当前自动触发规则

控制器只响应原有玩家染色成功事件，并根据事件前的选色和鼠标目标确定颜色与目标。失败点击、未解锁颜色、开局获得能力、单纯颜色解锁都不会触发。

| 目标/反应 | 当前结果 |
|---|---|
| 万能方块 `UniversalColorBlock` 自身成功变色 | 自动播放对应颜色覆盖效果 |
| 已挂 `GivingColorTestReceiver` 的测试物体 | 接色成功后播放覆盖效果；测试接收器本身不改变物体原外观 |
| 预先挂 `GivingColorEffectTarget` 的其他接色物 | 仅在原接色接口成功后播放覆盖效果 |
| 红色作用于水体并产生蒸汽 | 跳过覆盖效果，沿用水体原反应 |
| 红色作用植物，或蓝色触发藤蔓/植物生长 | 跳过覆盖效果，沿用原植物反应 |
| 蓝色作用于岩浆并生成深蓝色固体方块 | 跳过覆盖效果，生成物保持原反应结果 |
| 物体之间直接接触触发的反应 | 当前不触发；它不经过玩家染色成功事件 |

## 5. 效果与可调参数

效果由 `GivingColorDye.shader` 绘制在原纹理的非透明部分：

- **红色：**从点击位置向外扩散，带红橙色燃烧边缘。红色噪波扰动扩散前沿，使不同位置推进速度不完全一致。
- **蓝色：**从点击位置多次叠加浅色水彩扩散，逐渐加深至覆盖。蓝色噪波让扩散边缘更不规则。
- **绿色：**从中心向外辐射生长，枝条按层次分叉。绿色噪波影响分枝疏密和路径扭曲。
- **像素化：**只影响临时覆盖层的颜色和扩散采样，不改原材质的透明轮廓。

打开 `Assets/ta_source/GivingColor/Resources/GivingColorDye.mat`：

| 参数 | 用途 |
|---|---|
| 红色燃烧速度、蓝色叠染速度、绿色生长速度 | 各自动画的速度倍数，范围 0.25～4；1 为原速，数值越大越快 |
| 像素化强度 | 0 为平滑，越大像素格越明显；默认 0.7 |
| 红色橙边粗细 | 调整燃烧扩散外围的橙色边缘宽度 |
| 红色噪波量 | 控制红色扩散边缘的局部快慢变化 |
| 蓝色噪波量 | 控制蓝色水彩扩散边缘的局部快慢变化 |
| 绿色噪波量 | 控制各方向枝条的疏密与扭曲程度 |

材质值在下一次成功染色时读取。动画时长按以下关系计算：

```text
实际时长 = GivingColorEffectController 对应颜色的基础时长 ÷ 材质中的对应速度倍数
```

基础时长可在手动添加的控制器 Inspector 中调整；速度倍数在材质 Inspector 中调整。

## 6. 纹理与 Renderer 支持

- `SpriteRenderer`：覆盖层复用 Sprite、UV、翻转、排序层级和 Sprite 原纹理 Alpha。
- `MeshRenderer`：覆盖层为面向主相机的二维矩形，按可见 Renderer 包围盒定位，读取原材质第一张可识别纹理的 Alpha。复杂多材质、特殊 UV 或非相机可见面可能需要单独适配。
- 可读取 `_BaseMap` 或 `_MainTex`。没有纹理时按完整矩形处理。
- 其他 Renderer 类型当前不创建覆盖层。

## 7. 排查

- **完全没有效果：**确认原接色逻辑确实返回成功；目标属于上表允许的类型；场景中存在玩家颜色轮盘；目标有受支持且启用的 Renderer；颜色已解锁。
- **紫色/粉色错误 Shader：**查看 Unity Console 中 `GivingColorDye.shader` 的第一条编译错误。Shader 不可用时控制器会跳过绘制并记录错误，不应替换原物体材质。
- **效果播完后没有保留玩法染色：**这是预期边界。覆盖层会淡出；最终外观由原接色逻辑负责。`GivingColorTestReceiver` 只用于视觉测试，不会产生持久染色。
- **调整参数没有变化：**材质参数在下一次成功染色时读取；重新点击并确保目标接色成功。

## 8. 修改边界

允许修改本目录的 Shader、材质、效果控制器、效果目标组件、Inspector 和说明。不要为了接入效果修改原有玩家能力获取、颜色解锁、染色成功判定、物体反应或场景配置。`GivingColorEffectTarget` 创建的 Renderer、材质和覆盖网格均为临时对象，结束或重置时清理。
