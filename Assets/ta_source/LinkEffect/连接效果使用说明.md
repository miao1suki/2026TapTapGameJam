# 三色交互连线场景接入说明

这份说明用于把现有的交互连线效果接入游戏场景。重点是把组件放到玩家身上并接好材质，不需要给每个可染色物体单独添加连线脚本。

## 放在哪个物体上

把 `InteractionLinkEffect` 挂到**玩家根物体**上，也就是已经挂有 `PlayerController` 的那个对象。它需要和玩家的交互检测器、颜色轮盘在同一个玩家对象上配合工作。

绿色选色现在不经过本组件：绿色待机头和绿钩子由 `GreenHookAbility` 负责，本组件只绘制红、蓝预览。

2026-10-18：红蓝预览均只显示最近一个有效逻辑目标，按玩法碰撞体真实表面距离排序；同一多节物体先合并逻辑身份，不能把每个子碰撞体当作独立物品。绿色始终是实际单根钩绳，待机端点跟随鼠标世界位置轻微缓动，默认限制在基础染色范围加0.5格，挂接后绑定真实目标，不因移动鼠标脱钩。指针容差圈默认半径0.65格，只点击时查询附近合法目标；具体参数与边界见 [绿钩子说明](../../../Docs/Developer/GREEN_HOOK.md)。最近目标限制仅用于红蓝只读预览，不将实际鼠标点击染色强制改成最近目标。

运行时只预热并复用1个LineRenderer及其状态，不因旧场景仍保存`maxLinks`或`prewarmLinks=16`而创建多条线；这些旧字段仅保留反序列化兼容，不再控制显示或预热数量。最近目标切换时立即归还旧状态，新旧线不会叠加；没有新目标时可保留单条旧线溶解退场。换色/组件禁用清理状态，玩家销毁才销毁池。共享材质和PropertyBlock不变，不为每条线复制材质。顶点在复用数组内计算并一次SetPositions，长度直接在CPU计算，不再逐顶点SetPosition/GetPosition往返。无需手工修改或重建旧场景。

池化后仍要检查绘制调用链：性能采样发现`ResolveColor`调用的`ColorCatalog.Find(id)`原先通过捕获`id`的`List.Find`每次分配闭包和委托；现改为顺序for循环，保留精确ID/首个匹配项语义。不要重新换回捕获式查询，也不要把这项修复表述为整帧零分配；复测结果由整合者记录。

绿色视觉由`GreenHookVisualDriver`每个渲染帧在`LateUpdate`顺序1100更新，位于玩法相机顺序1000之后；物理仍由`GreenHookAbility`顺序-50的固定更新处理。不要把鼠标/绳尖刷新限制在FixedUpdate，或在相机移动前投影鼠标。绿线噪波种子固定，快速转向不会重新随机枝叶；光标容差圈使用Overlay深度常亮材质，无呼吸，中心/半径未变时复用几何。玩家身上原有染色范围呼吸圈不是这个光标圈。

Windows/Linux独立包聚焦时，菜单和玩法共用`Project.InputAbstraction.DesktopCursorPolicy`，以Confined限制在当前游戏窗口，避免多显示器鼠标跑出；不是Locked，不锁到中心。失焦释放，重新聚焦恢复。Editor和安卓不限制鼠标；实机多显示器切屏仍需PC包验收。

连线和 LineRenderer 会在运行时由组件自动创建为玩家的子对象，因此不用手动创建线条，也不要把这个组件挂到相机或每个可染色物体上。

## Inspector 里要设置什么

在玩家上的 `InteractionLinkEffect` 组件中设置：

| 项目 | 怎么设置 |
| --- | --- |
| 玩家交互检测器 | 选择玩家身上的 `PlayerInteractionSensor`。如果同一个对象上只有一个，通常可留空让组件自动查找。 |
| 玩家当前选色 | 选择玩家的 `PlayerColorWheel`；同一个对象上有颜色轮盘时也可留空自动查找。 |
| 颜色目录 | 拖入项目正在使用的 `ColorCatalog`。 |
| 像素线材质 | 拖入 `Assets/ta_source/LinkEffect/InteractionLink.mat`。 |
| 链条起点锚点 | 可选。若角色模型有合适的手部或身体锚点，可拖入对应 Transform；不设置时使用“无锚点时起点偏移”，当前默认 `(0, 0.3, 0)`，从玩家根节点沿本地向上偏移 0.3 个世界单位；纵向偏移不受角色缩放影响。 |
| 目标检测层 | 确认可染色物体的 Collider 所在 Layer 被包含在内。 |

检测半径沿用玩家 `PlayerInteractionSensor` 的扫描半径，不用在连线组件里再配置一份。

## 可调整的效果

- **线条生成时长（秒）**：只控制红蓝预览线整条淡入；绿钩子沿用其自己的出线/换点参数。
- **断开溶解时间（秒）**：没有新目标时，单条旧线消散所用的时间；切换到新的最近目标不会叠加旧线淡出。
- 在 `InteractionLink.mat` 材质 Inspector 中调节**链条粗细、像素大小、枝条噪波幅度、效果速度**。
- 材质中的**水纹外围效果强度**只影响蓝线中央主干周围的环绕线和波纹。设为 `0` 时只显示中央主干，数值越大外围效果越明显。

## 场景里的目标需要什么

可染色物体继续使用它原有的组件和 Collider，不用额外挂连线组件。连线会读取现有可染色目标，并且只在以下情况下显示：

- 玩家当前选中红或蓝颜色（绿色改由独立钩子负责）；
- 目标处于玩家交互检测范围内；
- 目标在检测层中，并且能响应当前选中的颜色。

实际红蓝染色仍由原有玩家染色流程负责；本组件只做可行性预览。绿钩子连接期间，拉物及接触/双方受阻等待仍允许普通行走，仅实际拉人或荡绳接管玩家运动；额外演出锁优先。连接不会因接触/受阻自动断开，挂绳全程及松绳后1秒不自动攀爬。荡绳松绳保留碰撞后动量，主动松绳默认8%助推、最多额外1世界单位/秒，并短时保护水平惯性；详见绿钩子说明。

水面波纹、鼠标预览等 `InteractiveWater` 内部碰撞体不参与颜色连线。水源/水流/气泡柱的交互范围以玩法对象自身 Collider 为准，避免合并放大时把特效检测范围当成接色范围。红色移动平台和曲柄升降平台是信号消费者，不属于可染色连线目标；合并本身不改变这一规则。

## 在测试场景里检查

项目唯一标准玩家是`Assets/_Project/Content/Player/Player.prefab`。在`Assets/Scenes/Test.unity`中找到具有`PlayerController`的玩家，查看其`InteractionLinkEffect`组件；不要因旧Hierarchy名称为`TestPlayer`而另建一套玩家预制体。配置引用交互检测器、颜色目录和像素线材质；起点锚点留空时使用默认偏移。

`Assets/Scenes/Pick.unity`的玩家也使用同样的连线效果，引用当前颜色目录和`InteractionLink.mat`，检测器与轮盘从同一玩家自动读取。场景使用PC管线当前的TA Stencil像素化参数，并保留之后的HSV阶段；不需要复制Test场景物体。

进入 Play Mode 后选择红、绿或蓝颜色，再靠近对应的可染色物体。没有选中这三种颜色、物体在范围外或物体不能响应当前颜色时，不会出现连线。

如果看不到效果，先检查玩家是否有 `PlayerController` 和 `PlayerInteractionSensor`，再确认颜色目录、像素线材质、目标 Layer 和物体 Collider 是否正确。

专项入口`Project.GreenHook.Editor.GreenHookVisualAudit.Run`用于检查实际渲染帧/相机顺序、光标圈稳定与松绳表现；移动、收集品和可选门/平台Timeline的配套入口见[绿钩子接入API](../../../Docs/Agent/Integration/GREEN_HOOK_API.md#验证入口)。仅在整合者的静音隔离工程运行，不在成员当前场景里执行，不以存在测试入口代替通过结果或实机验收。

## 协作交付

修改关卡摆放、实例参数或场景引用后，成套提交Scene、同名planning.json、meta及新增资源依赖；不能只提交Scene，否则其他成员无法继续通过关卡编辑器修改。不要为连线或绿钩运行时修复全量重建关卡。
