# 物体交互图接入规范

交互逻辑以具体物体为边界，颜色只是一项物体属性。所有策划可配置的关系都应进入 `InteractionObjectDefinition` 的图，运行时由 `InteractionManager` 编译执行。GraphView 只负责编辑数据，不参与游戏运行时路径。

## 开始前

1. 重新读取根 `AGENTS.md` 和 `Docs/Agent/PROJECT_CONTEXT.md`、`WORKING_AGREEMENTS.md`、`ACTIVE_WORK.md`、`SYSTEM_INDEX.md`；修改编辑器 UI 时再读 `EDITOR_UI_STANDARD.md`。
2. 确认 Unity 为 `6000.3.12f1`，远程为 `https://github.com/miao1suki/2026TapTapGameJam.git`，当前不是 `main`。
3. 不覆盖别人的未提交改动，不修改用户未保存的场景；脚本、资产和 `.meta` 一起维护。
4. 先在 `SYSTEM_INDEX.md` 找到现有物体组件契约，再决定复用方法还是新增运行时接口。不要恢复旧颜色工作台、旧颜色交互图或被排除的玩法。

## 数据与所有权

- `InteractionObjectDefinition`：一个具体预制体的身份、基础颜色和节点/连线数据。
- `InteractionObjectCatalog`：项目可交互物体目录。交互管理器打开时应自动同步关卡编辑器栏目，不要求先选中 Hierarchy 物体。
- `InteractionObject`：通用物体来源组件。已有 `ColorBlock` 的预制体直接在 `ColorBlock` 上绑定定义，不要再叠加第二个来源组件。
- `ColorBlock`：三色方块收集物理事件并提供公开方法；它不应重新拥有颜色交互图。
- `InteractionManager`：注册来源、编译图、派发触发器、执行条件/调度/效果节点。
- `ColorRuntimeService`：只负责颜色解锁、颜色属性、水体视觉和事件；交互关系仍由物体图表达。`HSVColorFadeManager` 只负责颜色层渐变状态。

一个物体只能有一个交互定义和一个主要事件来源。新增来源时必须明确谁负责 `Enter`、`Exit`、`Stay`、`Touched`，避免同一物理事件被两个组件重复执行。

## 需求拆分

把策划描述拆成以下五层，再开始画图：

1. **触发**：玩家进入/离开/停留、物体触碰/停留、经过时间、手动触发。
2. **上下文条件**：本物体、需要玩家、需要其他物体、受到颜色、受到物体 ID。明确 actor 是玩家还是其他物体，不能只依赖“当前碰撞对象”。
3. **流程控制**：延迟、顺序、分支条件、重复触发、一次性状态。需要持续效果时用 Enter 开始、Stay 维持、Exit 清除；不要只在 Enter 中设置永久状态。
4. **效果**：褪色、恢复、设置颜色、播放 Timeline、调用组件方法、输出日志。
5. **清理**：Exit、Disable、销毁、场景切换和重复进入时恢复集合、协程、玩家状态、生成物和事件订阅。

若需求同时涉及多个物体，分别为每个物体定义事件入口，再用“受到物体/受到颜色”条件收窄关系。不要把所有组合规则塞进颜色服务或一个全局管理器。

## 在交互图中工作

1. 打开 `Tools/2026TapTap/物体交互管理器`，先在左侧选择物体；红、蓝、绿方块及已同步道具应直接出现。
2. 用 `＋ 节点` 创建节点。触发节点通常没有输入端；条件、调度和效果节点接收流程输入并输出下一步。
3. 拖动输出端到输入端建立顺序。没有连线的节点不会执行；触发节点不能作为普通流程节点的输入。
4. 在节点自身填写值：颜色 ID、物体 ID、方法名、日志文本写入“值”；时间/延迟/褪色时长写入秒数；Timeline 写入资源引用；方法参数填写字符串参数。
5. 删除节点前确认连线也会被移除；保存后检查资产已标脏并写入 `Assets/_Project/Content/Interactions/Definitions`。
6. 一个常见接触链为：`玩家进入 → 需要玩家 → 调用方法(GameObject)`；离开链必须有对应的 `玩家离开 → 需要玩家 → 清除方法`。物体关系使用 `物体触碰/停留 → 需要其他物体 → 受到物体/受到颜色 → 效果`。
7. 解锁恢复链为：`手动 → 恢复(颜色 ID)`。颜色服务会提供基础恢复兜底，但定义仍必须在图中明确写出颜色值，方便策划检查和扩展。

## 接入模块的方法

### 现有组件

- 先提供小而明确的公开方法，例如 `EnterActor(GameObject)`、`ExitActor(GameObject)`、`ApplyBounce(GameObject)`、`SetInvulnerable(bool)`。
- 方法应可重复调用或明确拒绝重复调用；退出方法必须清除 Enter 设置的状态。
- `InvokeMethod` 支持无参数、`GameObject` 参数和字符串参数。需要结构化数据时优先新增运行时接口/节点，不要把 JSON 或隐式字符串协议塞进方法名。

### 新物体

1. 创建或复用预制体，添加 `InteractionObject`。
2. 在交互管理器中导入预制体，确认它进入目录和关卡编辑器栏目。
3. 配置基础颜色属性（没有颜色则留空），创建图并绑定触发/条件/效果。
4. 物理事件由组件转发给管理器；不要在新组件里绕过图直接调用另一物体的私有状态。

### 组合交互

组合规则以“双方具体物体 + 属性条件”表达。例如红蓝喷流应同时检查双方物体 ID/颜色，并从两个物体的配置读取起点、方向、距离和时长；蓝绿藤蔓应由蓝物体触发生成系统，再由生成系统按锚点搜索继续生长。生成物也必须有明确的所有者、销毁条件和重复生成保护。

## 测试顺序

### 资产和编译

- 每个定义都有有效预制体、唯一 `ObjectId`、有效节点 ID 和连线端点。
- 颜色钥匙的基础颜色和 `Restore` 节点值一致；三色方块的定义、预制体和目录引用一致。
- Runtime / Editor 编译 0 错误；`git diff --check` 通过；没有旧颜色管理器类型引用。

### PlayMode 事件矩阵

对每个新增物体至少验证：

| 场景 | 期望 | 必测清理 |
|---|---|---|
| 玩家进入 | 只触发一次 Enter 效果 | 不重复创建状态/物体 |
| 玩家停留 | 持续效果按帧或间隔工作 | 离开后停止 |
| 玩家离开 | 清除 Enter 建立的效果 | 再次进入可重新建立 |
| 物体触碰 | 只有目标物体/颜色组合触发 | 非目标物体不触发 |
| 物体停留 | 持续联动符合设计 | 任一物体 Disable 时解除 |
| 延迟/Timeline | 延迟后仍验证来源和目标有效 | 来源销毁时取消或安全退出 |
| 颜色解锁/褪色 | 初始褪色，解锁后材质和水体渐显 | 锁回后恢复褪色 |
| 重复进入/场景切换 | 不累积协程、订阅和生成物 | `OnDisable`/销毁清理完整 |

每次测试都要记录触发前后颜色、玩家状态、生成物数量和 Console 日志。不要只看镜头动画播放了就判定交互成功。

## 关键注意事项

- 触发器和碰撞器可能同时产生事件；用接触集合和帧去重，避免一帧多次执行。
- `Enter` 与 `Exit` 必须成对设计；玩家、其他物体和多个 Collider 要按来源对象去重。
- 预制体一旦绑定通用 `InteractionObject`，默认接触链中的每个“调用方法”都必须在该物体上有同签名公开方法。钥匙、机关等非方块物体不要直接套用方块方法名；要么在图中替换为物体自己的入口，要么提供明确的空操作/清理入口，避免运行时 Console 出现“未找到可调用方法”。
- 延迟协程、Timeline、生成藤蔓和临时材质都要有销毁/禁用路径。
- 运行时图执行有节点上限；循环图必须有终止条件或明确的时间/距离上限。
- 不把策划参数硬编码在方法体；需要调节的值放在定义、预制体或独立配置资产中。
- UI 入口用 UI Toolkit；正常空状态、缺失预制体和无效连线要在窗口中说明，不让策划依赖 Console。
- 如果缺少关键事实（弹高阈值、生命值 API、喷流资源、锚点预制体、藤蔓碰撞层、重复触发规则），先暂停该分支实现并向开发者确认，不用猜一个会改变玩法的默认值。

## 交付与持续更新

完成一个交互后同步更新：

- 对应 `Docs/Developer/*.md` 的策划使用说明；
- `Docs/Agent/Integration/*_API.md` 的接入契约和测试入口；
- `Docs/Agent/ACTIVE_WORK.md` 中自己的范围、验证、未验证项和待确认事实；
- 本 skill 中已经验证的新节点、清理规则或失败模式。

只有功能接近完成且用户要求时才提交/推送；推送前再次确认当前分支不是 `main`，不合并、不直接推送 `main`。
