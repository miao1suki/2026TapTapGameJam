# 存档改革

## 权威范围

本 Skill 是 `存档改革` 分支的存档产品约束。该分支内涉及以下内容时必须先完整读取本文件：

- 开始游戏、继续游戏、读档、自动保存和退出恢复。
- 真结局、假结局、新游戏和一轮游戏结束。
- 重生点、收集品、颜色钥匙、颜色能力、Boss 和传送地图进度。
- 成就、设置、按键映射等全局数据与单轮数据的边界。

本 Skill 与旧的多槽位存档说明冲突时，以本 Skill 为准，并在同一次变更中修正旧文档或旧 UI，不能默默保留两套规则。

## 产品不变量

1. 玩家不再选择、新建、读取或删除存档槽。
2. 一轮游戏只维护一个有效运行存档文件；允许同目录自动生成临时文件和备份，但玩家只感知“继续当前一轮”。
3. 没有有效运行存档时，玩家从开始游戏进入新的一轮，自动创建初始存档。
4. 存在有效运行存档时，开始游戏直接恢复这一轮，不显示选档界面。
5. 收集品属于当前一轮，随本轮存档保存；新一轮开始时清空。
6. 成就属于全局数据，永不随本轮存档创建、失败结局或真结局清档而删除。
7. 当前项目没有账号云存档。所谓“账号成就”在本项目内实现为本机安装范围内的全局持久化；除非之后明确接入平台能力，不要写成云同步。
8. 读取已有运行存档时，必须复用标准玩家的 RGB 故障死亡/复活表现：先把 `RgbGlitchEffect` 死亡层瞬间拉满，在故障遮屏期间恢复进度并把玩家传送到存档中的当前重生点，再按 `RgbGlitchSceneDriver.respawnFadeSeconds` 渐退揭示；不得改走通用加载背景、“加载中”文字或 `GameSceneLoader.TryStartRespawnTransition`。
9. 新建一轮时，收集品统计必须从 `0` 开始，不能继承上一轮或当前会话的已收集数量。
10. 没有有效运行存档时，点击“开始游戏”必须先在主菜单上闭全屏圆形遮罩；完全遮黑后再启动场景运镜，并从完全遮黑起等待 `2` 秒，再由 `Resources/story_start` 以已遮黑模式接手。玩家不能在遮罩前看到主角；完整开场结束后才提交初始运行存档。已有存档不得播放该开场或与其混用。
11. 暂停轮盘的收藏品页必须在标题下留出一整行空白，并在该行显示当前收集品图标、`: 已收集/总数`；成就列表从下一行开始，不能被统计行覆盖。
12. 项目工具必须提供 `Tools/2026TapTap/存档/重置当前运行存档`，仅在非 Play Mode 允许删除 `run.json` 及其临时/备份文件。

## 一轮游戏的范围

运行存档必须保存所有会让玩家重开应用后仍能合理续玩的进度，至少覆盖：

- 当前重生点和已激活重生点链。
- 本房间或本次运行所需的玩家位置恢复信息。
- 已收集收集品的稳定作者 ID。
- 每个收集品实例是否已收集；读档时必须逐个校对，已收集实例静默销毁/隐藏，未收集实例保留。
- 已解锁的场景颜色和已获得的玩家颜色能力，二者必须分开记录。
- 已消耗的颜色钥匙实例或等价稳定进度，保证重启后不会重复发放或遗失能力。
- Boss 已进入、正在战斗、已击败和传送地图解锁所需状态。
- 结局流程是否已经真正完成。
- 存档结构版本和必要的关卡/作者文档版本校验信息。

稳定作者 ID、重生点 ID、目的地 ID 是首选键。不要用数组下标、运行时 Instance ID、临时随机 GUID 或世界坐标作为跨启动主键；坐标只能在稳定 ID 不可用时作为兼容回退，并必须有校验。

临时机关状态、按钮瞬时进度、正在播放的 Timeline、收集飞行中间帧等不需要逐帧保存。房间重置仍按原有规则恢复。

颜色钥匙只能按“该实例实际已被收集”的稳定 ID 隐藏。不得因为某种颜色已解锁、某个能力已解锁或数量达到阶段就批量隐藏同颜色钥匙。当前钥匙消失来自原有 `DropItemBase` 收集完成后的回收生命周期，不是地图作者额外写的按颜色规则。

## 自动保存时机

只在状态稳定、可重复恢复的节点提交存档：

- 创建新一轮后。
- 新重生点激活或当前重生点切换后。
- 收集品结算完成并实际计入进度后。
- 颜色钥匙完成一次解锁阶段后。
- Boss 进入、击败或相关传送进度发生变化后。
- 真结局完成并准备清档前。
- 应用暂停、失去焦点或正常退出时做一次兜底 flush。

不要每帧、每次碰撞回调或动画中间帧写文件。连续事件可合并为一次延迟写入，但玩家死亡、返回菜单或退出前必须写完。

最低自动保存触发点固定包含：

- 首次激活/切换到新的重生点。
- 新收集品完成结算。
- 颜色钥匙完成收集。

## 新一轮与结局

- 只要运行文件缺失、无效或不兼容，开始游戏必须能自动创建初始轮，不能卡在错误界面。
- 损坏文件不得阻止进入游戏；记录错误并保留可诊断副本后创建初始轮即可。不要弹出手动选档流程。
- 收集低于 30% 时不得进入 Boss：拒绝 Boss 入场并回到第一关，当前轮和已有进度全部保留。
- 收集达到 30% 但低于 60% 时可以打完 Boss：Boss 击败后回到第一关，当前轮仍然保留，不能清档。
- 收集达到 60% 时按现有包含边界规则进入后续真结局演出；Boss 击败本身不是清档点。
- 只有真结局 Timeline 的最终完成节点明确执行“真结局完成”后，才删除当前运行存档。
- 真结局完成后还必须清理本轮运行时服务与临时对象，再通过现有场景流程回到主界面；不得直接改写场景或保留上一轮运行状态。
- 结局完成接口必须幂等，重复末帧、Timeline 重播或异常恢复不能重复清档、重复清成就或重复执行菜单跳转。
- 清档后下一次开始游戏必须从初始状态创建新一轮，不继承上一轮收集品、颜色钥匙、能力、Boss 或重生点。

## 真结局 Playable 接口边界

当后续接到真结局 Timeline Playable 时，Playable 只负责在演出真正结束后调用统一的“本轮完成”入口。该入口负责：

1. 将当前轮标记为已完成。
2. 删除单轮运行存档及其临时写入文件。
3. 重置收集品、颜色钥匙/能力、Boss、重生点和本轮临时对象。
4. 等演出允许交还控制后，经 `GameFlowController` / 世界菜单流程返回主界面。

Playable 不得自行散落实现文件删除、成就清空、玩家控制解锁或相机复位；这些动作必须复用统一的运行存档与场景流程接口。Boss 被击败、Timeline 开始播放、黑屏开始或玩家到达 `End` 锚点时都不能提前清档。

## 全局数据边界

以下数据独立于运行存档，创建新一轮或真结局清档时都不得删除：

- 成就解锁状态和成就累计进度。
- 音量设置。
- 按键映射和输入交互偏好。
- 移动端控件布局。
- 其他明确属于玩家本机配置的数据。

禁止在新游戏、失败结局或真结局流程中调用 `AchievementManager.ResetAllProgress()`。成就重置只允许作为明确的开发者调试操作。

## 实现约束

- 优先改造现有 `Project.Saving` 体系，不新增第二套互相竞争的存档管理器。
- 存档写入要原子化：先写临时文件，成功后再替换主文件；保留最近一次有效备份。
- 读取必须校验 schema、版本和关键集合；恢复过程应幂等，不得重复发奖、重复播放收集动画或重复解锁能力。
- 恢复顺序必须等场景、房间生命周期和稳定作者 ID 目录就绪后再应用；在玩家取得操作权前完成。
- 新游戏先清空本轮运行时服务和临时对象，再应用初始状态。不要用全局时间暂停或重新加载整个正式场景来假装重置。
- 新游戏在主菜单点击开始时先通过 `GameplayEntryCircleCover` 遮黑，再通过 `StartMenuFlowBridge.BeforeStartTransition` 请求场景运镜；`Assets/_Project/Content/GameFlow/Resources/story_start.playable` 通过 `Resources.Load<PlayableAsset>("story_start")` 获取，并读取 `StoryStartEntryHandoff` 以已遮黑状态接手。禁止等玩家出现在镜头里后才开始遮罩。
- 开始菜单中的“继续上次游戏”“选择存档”“新建空存档”和存档槽列表应移除或改造成不暴露槽位的单一“开始游戏”入口。
- 旧 `SaveGameService` 的多槽位 API 可以被替换、收窄或废弃；不要为了兼容空壳 UI 保留玩家可见的多槽位行为。
- 任何联网、云同步或跨设备账号成就都不属于本轮默认实现，不能擅自接入。

## 验证清单

交付前至少验证：

1. 无存档点击开始会先在菜单上闭圆形遮罩，完全遮黑后启动运镜；从全黑起等待 `2` 秒再无缝进入 `story_start` 台词，结束后创建初始轮。
2. 有存档启动会恢复到当前重生点、收集品、颜色解锁/能力和 Boss 进度。
3. 新重生点与收集品触发不会重复保存或重复发奖。
4. 应用退出后再进入仍能继续同一轮。
5. 失败结局回到 `Start` 后仍是同一轮，进度保留。
6. 低于 30% 无法进入 Boss，回到第一关后仍保留同一轮。
7. 30% 到 60% 以下可以打 Boss，击败后回第一关且不清档。
8. 达到 60% 后，Boss 击败只进入真结局演出，不能在击败当帧清档。
9. 真结局 Playable 最终完成会清档、重置本轮并回主界面，再启动自动创建全新一轮。
10. 真结局清档不会删除或回退成就、设置、按键映射和手机布局。
11. 损坏存档不会阻塞启动，并能自动进入新一轮。
12. 玩家界面不再出现手动存档槽、读档槽或“继续上次游戏”的伪功能。
13. 暂停收藏品页标题下保留一整行顶部空白，统计行显示当前 `已收集/总数`，第一条成就从下一行开始。
