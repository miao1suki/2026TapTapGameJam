# 颜色大洗牌开发入口

颜色解锁与玩家的当前规范：先读 `Docs/Agent/Integration/COLOR_UNLOCK_AND_STANDARD_PLAYER.md`。同色第一把钥匙只解锁全局场景颜色，第二把才授予玩家能力；`IsUnlocked/Unlock` 只用于场景，轮盘用 `IsAbilityUnlocked`，能力授予走 `UnlockAbility`。钥匙通过 `CollectColorKey` 一次结算一个阶段，禁用/销毁不得补结算。R/离区保留两种进度。唯一玩家预制体为 `Assets/_Project/Content/Player/Player.prefab`，不重建旧RuntimePlayer或Player(暂定)。

2026-10-12 区域生命周期规则优先：先读 `Docs/Agent/Integration/ROOM_LIFECYCLE_API.md`。离开世界图房间/通道或死亡/R重生只恢复相关区域的布置状态；门、按钮、已拾取钥匙及颜色解锁保留。已解锁物体回到刚解锁的行为，不重新锁色。R 不再只重置搬运，取消携带后进行区域重生。不得使用清空全局颜色的旧房间重置，也不得 Destroy 可恢复的作者物体。

本 Skill 是颜色系统开发的强制入口。

注意：万能方块现在作为前期辅助代理保留，自身显示纯色，并把同一颜色广播给左右上下四个紧邻目标，不拥有玩法能力。
功能组件的最新机关、水域、植物和参数要求以完整规范中的“2026-10-07 功能组件补充定稿”为准。
绿色选色使用主动绿钩子。合法点击当帧挂接并开始拉取/荡绳，出线仅视觉；默认发射5格，挂接维持额外3格，连续超距0.4秒才断，回到范围清零计时。不因接触、受阻或超时自动脱钩，跳跃/交互由玩家主动结束；死亡、重生、离区或目标失效清理。红蓝接触方块和基座逐物理步优先拉物、受阻改拉玩家并持续重评估；绿色接触方块/生长体、藤蔓和弹性植物作为荡绳锚点。绳可穿墙但实体不可穿墙，不可跨房间。接入先读 `Docs/Agent/Integration/GREEN_HOOK_API.md`，覆盖旧的连续停滞和自动结束规则。

## 不可违反的结论

- 颜色是钥匙解锁分组，不是物体的动态当前颜色。
- 旧 `ColorBlock` 适配器已经删除，不要再恢复动态染色方块。
- 物体的具体形态在放置时固定，不会跨颜色或同颜色切换形态。
- 一个功能只由一个组件负责。
- 功能组件直接处理触发、状态、表现、生成物和清理。
- 所有按格计算的距离、高度、检测范围统一读取 `IGridCellSizeProvider` / `BlockFeature.GridCellWorldSize`；组件不再暴露“每格大小 / 每格高度”。
- 母藤蔓通过“生长物预制体”生成 `Green_LadderSon`；生长物使用 `LadderSonFeature`，继承攀爬和出现动画，但不能再次被蓝色浇灌生长，只能被红色烧毁。
- 规划关卡编辑器中的连续竖列藤蔓仍逐格编辑；生成场景时只在同一房间、同列、同预制体、同格尺寸内组链。最下方是唯一母藤蔓，上方改为已存在的 `Green_LadderSon` 节段，最大生长块数为上方节段数，进入游戏时已长满。不要让蓝色交互在预置节段上重复生成，也不要在房间重置时删除预置节段。
- 机关控制方向是消费者绑定信号源：移动平台统一绑定基座、按钮、曲柄并订阅 `IMechanismSignalSource`；基座只检测能源并输出信号，不保存或寻找机关。
- 岩浆是全局唯一死亡方式；水、水泡、玩家控制和功能组件不得保留摔落伤害、摔落免疫或相关调试参数。
- 浮力水柱不设置最高顶起格数；只要气泡在玩家下方，且玩家碰撞体仍与任意蓝色物体重叠，就持续上浮，直到玩家整个身体离开全部蓝色体积。
- 左键颜色交互不再选择交互圈内最近目标；它先做屏幕射线命中前景物体，再检查目标是否在交互圈内，圈外和 UI 点击都不响应。
- 左键射线直接查找 `IColorApplicationTarget`；所有 `BlockFeature` 都实现该接色入口，由具体组件重写 `OnColorApplied` 执行红绿、蓝绿、红蓝等直接反应。
- `PlayerColorWheel` 的交互范围圈仅在持有选中颜色时显示并持续慢速闪烁；无选中颜色时隐藏。
- 范围圈使用呼吸淡入淡出。选中能力持续保留，成功染色/发射绿钩子不消耗选色；只有显式取消或进度重置清空。轮盘中央可取消能力。
- 未选能力时隐藏鼠标；选色后显示，成功使用不隐藏。ESC、主菜单等菜单态优先显示鼠标，暂停期间不得覆盖菜单光标。
- 横向绿块攀附按跳跃脱手下落，短暂禁止重新吸附；真实实体外转角通过玩家统一运动器保护交接，禁止用装饰物或虚构碰撞体抓附。死亡、禁用、房间重置清理转角状态。
- 持有待用颜色时点击无效目标，在居中下方显示 `这个物体好像不能与这个颜色反应`；目标超出交互范围显示 `无法触碰到这个物体`；颜色成功应用后显示 `染色成功`。三条消息沿用非法放置提示的 2 秒显隐、左入右出、白字黑描边和堆叠规则。
- 左键颜色交互必须先按鼠标世界命中点判断是否超出交互圈，再判断命中物体是否能接收颜色；圈外普通物体也必须显示 `无法触碰到这个物体`，不能误报为不能反应。
- 交互圈外的点击统一显示 `无法触碰到这个物体`，不区分圈外空气或圈外实体：空气按玩家世界平面换算点击点，实体按射线命中点计算距离。
- `Tab` 的“调色”动作只开关染色轮盘，并允许选择点击或长按触发。点击为开关式，长按为按住式；玩家驱动的 2D/3D 切换已删除，`F` 负责曲柄和搬运交互。按钮仅玩家踩踏或三色接触方块压下，不注册按键交互目标。
- `PlayerInputDriver` 只把输入转换为 `PlayerController` 上的轮盘/移动/跳跃命令；`PlayerColorWheel` 不直接读取输入。
- 藤蔓是实体阻挡物，按格距离进入攀爬；W 上爬、无输入自然下滑、S 加速下滑、空格固定，AD 可离开范围，且暴露对应速度参数。
- 攀爬输入补充：朝藤蔓方向的水平键也会上爬，反向水平键离开；按住朝藤蔓方向并按跳跃键向外上方蹬跳，短暂不重新抓附。该规则优先于上面的“AD 可离开范围”。
- 弹跳植物必须是实体阻挡物并只在正确落点触发一次弹跳；按钮检测脚部/方块底部压力，支持一次保持或持续压住；移动平台碰到实体方块后反向。
- 能源方块和万能方块共用独立 `CarryableFeature`。能源方块只有在自身 `IColorObject.IsActive` 时才可搬运；万能方块没有颜色对象，常态可搬运。
- `CarryableFeature` 不实现 `BlockFeature` 颜色形态生命周期；它只负责注册拾取目标、头顶跟随和放下动画，颜色门控由同物体 `IColorObject` 自动决定。
- 玩家本体默认按 1×1 格参与相邻检测；只拾取玩家占格上下左右紧邻的 `CarryableFeature`。`F` 固定选择拾取队列第一个目标，玩家先冻结 0.1 秒，随后目标关闭 Collider、置顶并由 DOTween 移到玩家头顶。
- 携带时玩家只能移动和冲刺，不能跳跃、调色、交互或染色。`Q` / `E` 分别请求放在玩家左侧 / 右侧；只检查玩家占格该方向的紧邻格，非法时保持携带，不移动物体，弹字由后续字幕管理器统一接入。
- 左右放下前先沿放下方向从玩家中心做 `1.1` 格射线；命中玩家和当前搬运物之外的任何 Collider 直接判非法，防止单层薄墙被目标格检测绕过。
- 目标格还要先检查 `LevelEditorPlacedBlock.ContainsCell` 的网格占用；同格已有方块或道具时禁止放置，不得只依赖物理 Collider。
- 忽略玩家和当前搬运物时不能按共同 `root` 判断；规划地图的方块可能共享 `__PlanningMapGenerated` 根，必须只忽略自身层级。
- 三把颜色钥匙的 Timeline 必须强制正交 2D、固定前方朝向，关闭看向角色并锁住相机纵深；只允许平面平移和推拉缩放，避免 3D 场景侧壁露出。
- 三把颜色钥匙共用 8.5 秒运镜：0–0.5 秒先追踪到玩家当前普通机位，0.5–3.5 秒向上移动并把视野范围扩大到 1.5 倍，3.5–5.5 秒停留，5.5–8.5 秒位置和镜头视野同时倒放。
- 颜色钥匙在倒放开始（5.5 秒）时立即释放玩家控制锁；相机倒放、颜色渐显和拾取视觉并行收尾，不能等演出或回收结束才解锁。
- 可搬运物必须记录被拿起前的原始位置。`Respawn` 绑定显示名称为“复活/重置搬运”；携带中按下它或玩家死亡时，都通过 DOTween 把物体送回原始位置，动画完成后恢复 Collider、结束携带并释放玩家控制。
- 携带提示由 `WordNoteUI` 显示，内容包含当前实际按键的左右放下、当前复活/重置键；它位于下方分区、参与堆叠，显隐各 `0.5` 秒。非法落点也在下方分区，显示“位置非法，请留出足够空间”并存活 `2` 秒，显隐与左移组合入场、显隐与右移组合退场，各 `0.5` 秒；两者都白字黑描边。
- `WordNoteUI` 入退场支持显隐、水平移动、竖直移动、缩放四条独立组合通道，方向、距离、时长、初末速度和变速比例都可编辑。
- 万能方块自身显示纯色，并向左右上下四个紧邻的 `IColorApplicationTarget` 广播颜色。
- 万能方块不是颜色源、不是能力本体，但可以像能源方块一样被携带。
- 物体之间的固定反应使用类型安全接口，不经过交互图。
- 所有可拾取掉落物必须继承 `Project.Items.DropItemBase`；`OnEnable` 只走出现阶段，拾取通过 `TryBeginCollection` 进入收集阶段，收集表现结束后才由基类回收。
- 掉落物的出现、收集、停止 Tween 必须写在 `DropItemBase` 的动画钩子里，子类只处理具体拾取效果；不得在子类触发入口直接 `Destroy`、`SetActive(false)` 或提前关闭 Renderer。
- 当前尚未导入 DOTween，禁止引用 `DG.Tweening`；导入后仍只在 `DropItemBase` 中实现动画，不在每个掉落物子类重复写 Tween 生命周期。
- 高频路径禁止反射、字符串方法调用、全场景扫描和无意义协程。
- 新增或修改自制组件时，必须提供中文 UI Toolkit Inspector、Foldout、条件显隐和可调试状态。

## 工作流程

1. 完整读取 `Assets/_Project/Code/Systems/ColorBlocks/SKILL.md`。
2. 按根 `AGENTS.md` 读取项目持续文档。
3. 盘点改动涉及的预制体、场景、颜色资产和现有图引用。
4. 先补直接组件路径，再删除旧图路径。
5. 运行时验证锁色、解锁、房间重置、重复进入和清理。
6. 同步更新功能文档与 `Docs/Agent/ACTIVE_WORK.md`。
